## Latest continuation delta

Implemented the disk-backed identity/canonicalization step in `LocalCatalog.kt`: removed the whole-import printing-ID set and Oracle/card map. Each bounded batch checks printing identity and canonical identity through existing primary keys inside its real write transaction. Both checks return at most one row. An existing canonical payload is decoded and compared with the accepted `sameCanonicalGameData` function, preserving numeric-value comparison, unknown/absent distinctions and the exclusion of acquisition/printing metadata. The canonical digest remains stored but is not used as a substitute for that comparison. First representatives alone write canonical rows, faces and FTS rows. Scalar counts advance after successful batch commit; final SQL count validation and active-generation transaction are retained. Existing late-commit cancellation cleanup guard is unchanged.

Added three native test methods: duplicate IDs and nonadjacent canonical conflicts both within/across batches (`batchSize` 128/1) preserve the prior active generation/index and leave no staging generations; numerically equal decimal spellings and different printing metadata produce two printings with one canonical/FTS row; cancellation immediately after a real first printing write rolls back the batch and preserves the old generation/index. Existing genuine fixture import/reopen, stale cursors and late-activation cancellation tests remain. The new constructed cases are explicitly synthetic and are not corpus evidence.
