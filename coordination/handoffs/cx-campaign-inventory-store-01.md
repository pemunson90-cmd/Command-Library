## Private format version1 (frozen framing)

All integers big-endian; count/length fields u32 encoded with signed Java int and validated nonnegative. Framed ID is u32 byte length1..1024 + strict UTF8 nonblank bytes. Lists use unsigned UTF8 ID order with strict uniqueness. No canonical normalization of identity/text/reasons/evidence.

- **CLID1 descriptor**: ASCII `CLID`, u16 version1; u32 public-change-ID count then framed IDs; u32 merge count then (framed requested-ID, framed survivor-ID, i32 nonnegative quantityAdded); u32 permanently-introduced-ID count then framed IDs. Each count<=1024; whole descriptor<=4MiB. Public IDs exactly select physical changes with active before OR active after; public null→null reservation effects omitted. Introduced IDs exactly select absent-before/present-after effects, including new active survivors AND absorbed inactive reservations. UNDO introduces none; absorbed inactive reservations are unchanged and omitted from its physical/public changes. SHA256 of exact descriptor stored; decoded lists/counts and merge/image relationships checked.

Present image then u8 active0/1, i64 lot revision, i32 quantity>=0, i32 CLOL payload length6..8MiB, u16 payload version1, exactly64 ASCII lowercase SHA256 characters of complete CLOL bytes. Absent image has no further bytes. Physical after images always present; reservations never deleted. The SQL side metadata and actual blob lengths/types are validated before fetching descriptor/images. Descriptor + BOTH sides of every physical image share one16MiB operation budget.
