## SQL statement contract

The complete column/index/FK declarations are in `schema/RulesTables.kt`; additive creation SQL is in `schema/Migration1To2.kt`. All unspecified fields below are NOT NULL. `TEXT?`/`INTEGER?` are nullable, with no manufactured defaults. Timestamp pairs use epoch seconds plus nanoseconds. Public model payload encoding belongs to feature rules; metadata projection nulls do not replace complete Knowledge states.

- `rules_corpus`: `generation_id TEXT` PK; `provider/language/status/content_uri/display_name/source_payload/provenance_payload/content_sha256 TEXT`; `upstream_version/source_uri TEXT?`; `effective_at_epoch_seconds/source_date_epoch_seconds/activated_at_epoch_seconds INTEGER?` with corresponding `effective_at_nano/source_date_nano/activated_at_nano INTEGER?`; `observed_at_epoch_seconds/observed_at_nano/observed_bytes/entry_count/reference_count/payload_schema_version INTEGER`. Index `(provider,status)`. SHA-256 computed from exact incoming bytes; observed time separate from unknown source/effective date.
- `rules_active`: `singleton_id INTEGER` PK, repository always uses **1**; `generation_id TEXT` indexed FK to `rules_corpus.generation_id`, DELETE/UPDATE NO ACTION. Singleton-key domain is an adapter invariant, not a hidden trigger or CHECK. Activation updates this pointer and corpus statuses atomically.
- `rule_entry`: `corpus_id/provider/local_id TEXT` composite PK; `kind/text/entry_payload TEXT`; `number/title TEXT?`; `ordinal INTEGER`. FK `corpus_id` to corpus generation with DELETE CASCADE; unique index `(corpus_id,ordinal)` preserves stable order across providers. Payload preserves complete RuleEntry including Knowledge, references and provenance.
- `rule_reference`: PK `(corpus_id TEXT,from_provider TEXT,from_local_id TEXT,ref_ordinal INTEGER)`; `raw_target/evidence_payload TEXT`; `resolved_provider/resolved_local_id TEXT?`. Composite FK source entry with DELETE CASCADE. Resolved pair coherence is adapter/codec invariant; resolved targets may truthfully be unknown or outside this corpus, so there is no target FK. Raw target and evidence survive either state.
- `rules_import_attempt`: `attempt_id TEXT` PK; `generation_id TEXT?`; `source_payload/attempt_payload/phase TEXT`; `started_at_epoch_seconds/started_at_nano/payload_schema_version INTEGER`; `finished_at_epoch_seconds/finished_at_nano INTEGER?`; `failure_payload TEXT?`. Index `(started_at_epoch_seconds,started_at_nano,attempt_id)`. No generation FK, so audits remain after failed staging or retired corpus deletion. `attempt_payload` preserves complete LocalRulesImportAttempt, including Knowledge for finishedAt; source and failure projections remain available separately.
- `rules_text_fts`: FTS5 indexed `title/text`; UNINDEXED `corpus_id/provider/local_id`; tokenizer `unicode61 remove_diacritics 2`, exactly the catalog policy. No FTS FK. Caller inserts `COALESCE(title,'')` only into FTS (nullable entry metadata remains null), writes FTS together with entry staging, and explicitly deletes FTS with retired/staging corpus in the same transaction.

Named SQL parameters remain required through Database port. Corpus-qualified lookup joins hits on all three `(corpus_id,provider,local_id)` fields; default search pins active singleton pointer and pagination pins corpus/ordinal. Import-attempt durable terminal failure is written independently after staging/activation rollback. None of these tables is permission to infer unknown source metadata or activate an incomplete corpus.
