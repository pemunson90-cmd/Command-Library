# Bounded artifact descriptor compatibility ruling

2026-10-13. Design ruling only, for root's `cx-artifact-locator-01` packet; no repository edits. Reviewed root working source at HEAD `b06b4882c68a8a99ca24ed51f73c70f717ce3172`, task card, AGENTS/CONTINUE, D-20–D-22/D-26, SPEC H06/N01, Android binding design/review and `/workspace/scratch/artifact-locator-review.md`. Platform API findings below rely on that retained exact-source review, not a repeated platform survey.

**Choose B: retain minSdk23 and all provider functionality, use atomic close-on-exec duplication on API30+, and explicitly make no final-PFD close-on-exec guarantee on API23–29. No JNI adapter or baseline increase is necessary for this boundary.**

## Why this is within the requirements

The product requirements do not mandate FD_CLOEXEC on every supported release. The provider task itself specifies O_CLOEXEC on the initial secure open followed by public PFD.dup. The source review correctly identified that dup loses the flag; that is a real limitation and must not be hidden. However, making the *returned* FD close-on-exec on every legacy release is additional engineering hardening, not a separately approved product/privacy guarantee.

The actual boundary is a nonexported, nongranting, same-process provider for trusted internal consumers: verified completed artifact only; exact canonical active URI; same UID; atomic no-follow/nonblocking identity-checked read; full callback acquisition pin; lexical resolver ownership; and synchronous registry removal plus closure of every tracked adapter-owned FD before pin release. A same-process public dup does not convey the descriptor to another UID. Without a child process inheriting it, omission of FD_CLOEXEC does not extend that descriptor's lifetime beyond its ordinary close.

This reasoning relies on the stated no-subprocess/no-exec/no-untrusted-dynamic-code policy for the consumer process. The current production scan found no ProcessBuilder, Runtime.getRuntime, .exec, DexClassLoader, InMemoryDexClassLoader or sharedUserId matches. This scan supports, but does not prove, the whole-process policy across future code or dependencies. SPEC H06 restricts AI tools to bounded search/get-card reads and forbids remote content invoking shell/file/credential tools. D-26 defers native inference runtime integration. UiAutomation's external shell test is not an app-process exec of the live artifact FD.

Do not call this resistance to hostile same-UID code: such code can already duplicate/read the FD or access app-private storage. CLOEXEC also does not prevent fork-only inheritance, deliberate duplication or explicit descriptor passing. The guarantee remains trusted-consumer lifetime control, not revocation of arbitrary Linux FD copies. These limitations apply even on modern Android.

D-22 prioritizes Fold7 and permits needed technical changes, while retaining min23 unless a change is needed. B supplies the extra atomic exec hardening on the primary modern target without removing old-device functionality or introducing native build/ABI/16 KiB verification surface solely for a legacy hardening property outside the current threat boundary. A is a defensible fallback if subprocess inheritance later enters scope; C is unnecessary now. No new user ruling is needed for this bounded technical choice.

## Exact implementation instruction

1. Keep the current Os.open flags, fstat checks, monitor serialization, cancellation admission checks and cleanup structure unchanged.
2. After successful identity verification, on SDK_INT >= 30 use public `Os.fcntlInt(temporary, OsConstants.F_DUPFD_CLOEXEC, 0)` and transfer the resulting integer FD exactly once to public `ParcelFileDescriptor.adoptFd`. Isolate/annotate the API30 helper as needed for lint/verification. Preserve ownership cleanup on every failure path; never leave an unowned duplicated integer FD. Do not follow dup with F_SETFD: that would reintroduce an exec race.
3. On API23–29 use public `ParcelFileDescriptor.dup(temporary)`. Document explicitly that the final owned/returned descriptor has no CLOEXEC guarantee on those versions. Do not use hidden APIs, reflection or numeric fcntl workarounds. Continue closing the original temporary FD in finally on every version.
4. Keep all returned PFDs tracked under the same lease and all ContentResolver wrappers/streams lexically closed inside the callback. No callback handle duplication, detachment, escape, independent cross-process consumers or async cleanup. Reject new opens before attempting every tracked close; preserve primary failures and the full acquisition pin through cleanup.
5. Remove only the locator's post-action `.also { ensureActive(); cancel.throwIfCancelled() }`. Return a normally completed callback result without an extra late cancellation exception. Retain entry, actual read and callback-controlled cancellation/commit semantics plus synchronous finally invalidation. This does not broaden the current helper to cover outer importer acknowledgement.
6. Root updates the task/design guarantee and links this ruling to supersede only the earlier all-legacy final-PFD CLOEXEC blocker. Retain the prior source finding as history. Add the whole-process no-subprocess/exec/untrusted-code assumption to the active lifetime contract; any future app/dependency subprocess execution, native engine spawning, cross-process consumer or dynamic executable code requires renewed security/lifetime review before integration. Do not impose a new end-user approval workflow.
