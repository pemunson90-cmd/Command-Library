## Concrete blockers/corrections

1. **Source API must suspend.** Use `public suspend fun catalogSource(jobId: EntityId, cancel: CancelToken): Outcome<CatalogBulkImportSource>`; `withArtifactFile` and `status` suspend. No `runBlocking`, provider database lookup, or blocking graph initialization.
2. **The proposal overstates current pin lifetime.** `LocalBulkCatalog.kt:141` invokes the binding, but ambiguous COMMIT reconciliation occurs in the outer catch at lines144–161, after the binding has exited. A binding implementation alone cannot hold the pin through that reconciliation. If whole-import acknowledgement remains the guarantee, move the relevant bounded reconciliation inside the pinned operation through a separately reviewed small internal importer change. Preserve the existing successful-commit/cancellation semantics. Otherwise explicitly narrow the promise and review its interaction with Task4 removal acknowledgement; a file guard does not supply an install/revocation fence.
3. **Atomic provider opening must be specified.** A regular-file/canonical check followed by `ParcelFileDescriptor.open(file, MODE_READ_ONLY)` follows symlinks and leaves a check/open race. Open the registered private path with API23 `Os.open` using `O_RDONLY | O_NOFOLLOW | O_CLOEXEC`, `fstat` the opened FD as regular and compare captured registered device/inode/size identity, then create the owned PFD by `ParcelFileDescriptor.dup(fd)` and close the temporary FD in `finally`. Trust the fixed private parent directory explicitly; final-entry NOFOLLOW is not arbitrary ancestor protection. The current durable-file helper also checks before ordinary Java opens, so do not claim it proves adversarial pathname-race safety. No hostile same-UID-process guarantee is possible; test namespace violations fail closed and preserve EOF byte/hash validation.
4. **Make the registry race protocol concrete.** Under one synchronous registry lock, admit only ACTIVE leases, validate URI/mode, open/track the FD, and perform a final cancellation check; an aborted open closes its FD. Lease exit atomically marks CLOSING/removes admission, attempts closure of every retained raw PFD, and only then releases the artifact pin. Cleanup must run despite coroutine cancellation and close failures, attempting all closes and preserving the primary failure. Caller resolver wrappers/streams remain lexical `.use` owners and must close before exit; raw-PFD closure alone does not release a resolver wrapper's provider reference. No duplicated/detached descriptors, detached reads or external consumers. A CancellationSignal precheck does not cancel subsequent stream reads: explicitly bridge the caller token/coroutine cancellation and check reads. Keep typed/openAsset/openFile overloads on this single policy, whole-file offset0/declared length-1, allowing `*/*` without conversion.
5. **Production trusted profiles are still absent.** “Reviewed exact source/version/query policy” and “finite limits” are instructions, not an implementable table. Before publishing a production facade supply exact intent/source IDs and versions; `queryPolicyVersion`/`profileVersion`; numeric transfer/artifact/decoded/records/pages/page/record/chunk/nesting bounds; endpoint IDs and exact origins/redirect sets; accepted framing/compression; checksum/expected-size/source-date authority; timeout/retry/header policy; refresh admission; and disk reserve policy. Do not turn caller metadata into authority or use an accept-all/test profile in production. The smallest initial production profile should be the exact English search URI already in `EnglishSearchPageCodec.INITIAL_URI` and PERSONAL-SOURCE-REVIEW, validated page grammar, `lang=en`, no redirect, >=600ms spacing, one attempt/NEVER_AUTOMATIC, no secret and actual app/version User-Agent. Concrete named bounds remain needed. Bulk/default/all/Oracle/artwork profiles stay unimplemented without exact metadata identity, data.scryfall.io URI rules, language-consent matrix and declared gzip/JSONL bounds; Default Cards does not certify English. Rulings and offered Wizards TXT need their own exact profiles and consumers, not admission through the card facade.
