## Required corrections

1. **Stale start/resume can stop the current writer — lines 83–88.** `queue()` cancels/joins the registered worker before loading and validating expected revision and allowed state. Calling stale `start()` during RUNNING returns failure but cancels the valid transfer and leaves it INTERRUPTED, retaining its ambiguous budget reservation. `resume()` shares this path. Validate under the control lock before any cancellation or file mutation, as `stop()` already does, then revalidate as needed after quiescence. Scratch regression `staleQueueMustNotCancelCurrentRunner` fails on the stale-start case; shared resume-path consequence is source inspection.

2. **Token cancellation cannot interrupt a held-pin/lock wait — lines 554–555, 586–594 and other plain withLock waits.** Coroutine cancellation cancels Mutex waits, but the separate CancelToken does not. With one callback holding an artifact pin, a second `openArtifact()` with a cancelled token remains suspended indefinitely until that first callback releases. The probe remained blocked after 1.1 seconds of test-scheduler time. Use token-aware acquisition/wait handling across admission/control/file/search waits and joins, while preserving ownership until actual writers/commits settle; do not release a durability fence merely because a waiting caller timed out. Add both token-only and coroutine regressions.

3. **Requested deletion has no durable crash-recovery continuation — lines 614–619 versus recover line 529.** Removal atomically deletes the artifact row and marks CANCELLED, then physically deletes its files. A crash between those actions leaves downloaded bytes on disk; recovery skips CANCELLED jobs. A deterministic probe materialized the exact post-transaction/pre-delete state and recovery returned success with the artifact still present. Persist a distinguishable removal-pending intent/tombstone before deleting, make physical cleanup and directory sync idempotently recoverable, and clear the intent only after durable cleanup. Do not equate ordinary user cancellation (which may retain bytes) with explicit removal. Cover interruption after DB commit, file deletion, and directory-sync failure.

4. **Removing one consent's artifacts interrupts unrelated jobs — lines 604–610.** `removeArtifacts()` cancels every worker before filtering jobs by consent. The two-job probe confirms that removing completed job B stops unrelated running job A. Enumerate target jobs and cancel/join only matching writers under their controls. Recheck current `row.consentId` after acquiring the target lock: current code filters an earlier list snapshot and does not recheck the loaded row, so a concurrent replacement consent can change membership before deletion. The unrelated-worker defect is runtime reproduced; the membership race is source inspection.
