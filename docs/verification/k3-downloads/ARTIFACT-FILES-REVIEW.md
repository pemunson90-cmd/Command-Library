# Artifact file helper review — corrections required before durability approval
Reviewed untracked `DurableArtifactFiles.kt`, `AndroidArtifactFiles.kt`, and `DurableArtifactFilesTest.kt` over HEAD `c0bd1f02bdbcea369fddc9602ecb91c3a494f415`; no repository edits. Reviewed helper SHA-256: `0efa5b4d79176accce69742ec54796b163131d0f2ea7f81fcf637d1965613833`.
**Fix dangling-symlink detection:** `canonicalFile == absoluteFile` and `exists()` both admit a dangling link. An independent local Java21 probe confirmed `renameTo` replaces that link. Use a no-follow/lstat check through the Android adapter, reject all existing candidate entries, and add a dangling-target regression. Current regular-symlink test does not cover this.
**Make directory creation durable:** constructor `mkdirs()` can introduce an unsynced entry in the directory's parent. Syncing only the new directory after file creation cannot guarantee that parent entry survives power loss. Require a previously durably provisioned directory, or sync each created directory and its parent with failures propagated before successful operations.
**Close/document the shared namespace race:** `target.exists()` followed by `renameTo` is not atomic non-overwrite. A per-job guard does not exclude another job creating that target. Enforce a directory-wide mutation guard across all helper instances/process writers, or an equivalent exclusive namespace/allocation protocol covering partial and candidate keys; a mere probabilistic unique name is not proof of non-overwrite.
Append arithmetic/chunk bounds are overflow-safe; exact offset, fd.sync, and short-file rejection are sound under exclusive ownership. Verification uses bounded memory and rejects size changes, but same-length mutation requires the guard. maxBytes bounds file length, not cumulative network transfer: the runner still owns durable request-budget reservations.
Promotion syncs file before rename and propagates real Android directory-fsync errors; rename success plus sync failure leaves a candidate that needs reconciliation. Caller must persist attempt-owned candidate identity first, hold exclusion through verification/consent/CAS commit, and never publish COMPLETED after sync failure or resurrect revoked/cancelled work.
Tests cover existing-file collision, limits, tails, known SHA-256, regular symlink rejection and post-rename sync failure with a stub sync adapter. Root's catalog compile/tests were in progress; reviewer ran only the Java path-semantics probe. Android adapter, DB/service coordination and power-loss behavior remain unverified.
Next: correct the three filesystem boundary issues, run focused tests, then review production binding separately; no DownloadService, Android durability, or full-service acceptance follows from this helper review.
