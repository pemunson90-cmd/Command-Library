# K3 full English acquisition/import: bounded architecture review

Review base: `f4760ba2451ee369519ee6e0220ff6352fc60fc5`, clean worktree observed. Read-only review; no repository files changed. This is implementation design, not source approval, corpus measurement, execution evidence, or K3 acceptance. All 64 requirements and 213 parity obligations remain binding; full Android v1 and Fold7 remain the delivery target. Historical D-23 small-file delivery is not the new finish line.

## Findings that determine the implementation

- `LocalCatalogContracts.kt` hard-clamps input to 8 MiB and 10,000 printings. `LocalCatalog.kt:109` exclusively constructs `JsonArrayFramer`; bounded `JsonLinesFramer` already exists but is not connected. No gzip adapter exists in this path. Merely increasing constants does not finish the importer.
- `LocalCatalog.kt:84` accepts only a named `content://` source. Keep this honest local boundary; downloaded app-private artifacts need an explicit additional source descriptor rather than forged content URIs.
- `LocalCatalog.kt:196` deletes every STAGING generation during initialization. That conflicts with durable import recovery. Cleanup currently cascades an entire generation within a one-second cleanup timeout; this does not establish bounded full-corpus cancellation or startup latency.
- Good foundations to retain: separate staging generations; bounded batches; provider-qualified IDs; canonical equality checks; one FTS row per Oracle/language; exact final length/hash validation; transactionally activated pointer; no cancellation check after a confirmed commit. Storage already has a rollback-only transaction latch and a final precommit cancellation boundary.
- Schema v2 contains catalog tables and comprehensive-rules tables, but no card rulings, jobs, import checkpoints, legalities, or typed search projections. Full Oracle JSON payload storage is not an indexed filter implementation. `CatalogCounts.rulings` currently returns zero, not verified rulings coverage.
- `NetworkClient` is declared in core; `:data:network` is absent. `DownloadJob`, `Ruling`, `DownloadIntent`, `ConsentRecord`, and progress DTOs exist as declarations; durable adapters/control ports do not.

## Minimal additive implementation

### 1. Explicit acquisition and import manifests

Add a reviewed immutable `CatalogAcquisitionPlan`/artifact manifest with provider, dataset/version, source and allowed final origins, source date, framing (`JSON_ARRAY`/`JSONL`), compression (`NONE`/`GZIP`), advertised representation size, separately optional trusted checksum, observed language scope, English selection policy, notice, and a versioned budget profile. Keep downloaded bytes, decompressed bytes, parsed records, accepted English records, skipped foreign records and malformed/rejected records distinct. A locally computed hash proves identity, not authenticity or completeness.

Replace the tiny hard ceilings with independently bounded `Long` wire/artifact bytes, decompressed bytes, record count and staging storage; retain bounded chunk, record, nesting and batch sizes. Use overflow-safe subtraction checks. Determine numeric corpus ceilings from the genuine selected current feed, maximum observed record and resulting DB/WAL size with documented growth headroom. Do not label guessed GiB/record constants verified. Existing acceptance budgets remain import <=10 minutes, peak RSS <=450 MiB excluding loaded LLM, base <=300 MiB, cancel <=1 second, DB p95 <=150 ms, visible interaction <=250 ms. Record actual Fold7 results; emulator measurements supplement them.

Pipeline: bounded network chunks -> app-private partial artifact -> verified complete artifact -> bounded decompressor -> selected byte framer -> explicit language gate -> typed record mapping -> bounded transactional staging batches. No full-file ByteArray/String/List, no unbounded producer queue. Compression footer/CRC, truncation, trailing bytes and supported gzip-member policy must be checked before activation. Bound inflated bytes independently of compressed size; define which representation each checksum and offset measures. Wire-format probing must not silently guess incompatible framing from a filename.

Language policy is a release blocker until a source path is settled: downloading `default_cards` and discarding foreign rows afterward still transfers foreign bytes when the source includes fallback foreign printings. It does not satisfy explicit consent before non-English acquisition. Use an independently verified English-only source/endpoint, or an explicit scoped consent flow that accurately describes the mixed transfer. Do not relabel broad mixed-corpus download as English-only. A user-selected local mixed file can be filtered locally with explicit imported-language status; that does not authorize its automatic remote acquisition. Filter `lang == en` before English mapping; malformed/missing language is a validation failure, not silently discarded data. Preserve foreign user-owned IDs unresolved without starting transfers. English feed completeness and coverage must be checked against the selected producer semantics; neither `oracle_cards` nor a sample proves every English printing. Paged search acquisition needs explicit stable-snapshot/completeness evidence and safe continuation handling.

### 2. One shared NetworkClient and persistent job controller

Implement the existing core port in `:data:network`; inject one application-scoped instance. Catalog/rules/model consumers use this shared transport, not independent download clients. Honor source-scoped <=8 requests/second, Retry-After, bounded retry/backoff, connect/read timeout and cancellation that closes response bodies/sockets. GET retry does not permit blindly appending repeated data. Potentially charged ambiguous requests remain never automatically retried. Validate HTTPS/origin and each redirect; strip credentials on cross-origin redirects and never forward arbitrary request headers by default. Redact credentials, signed URLs and raw bodies in diagnostics.

Add capability ports such as `CatalogDownloadControl` (`plan`, `start`, `pause`, `resume`, `cancel`, bounded `jobs`, `observe`) and a separate import runner. Existing `refresh()` can delegate once its complete semantics are actually implemented; do not register a partial aggregate. Public DTOs need durable job status beyond current phases: paused, waiting for network/Wi-Fi/consent, recoverable interruption, failed and completed; phase remains a separate progress dimension. Progress units must distinguish bytes from records. Add job revision/attempt, manifest identity, final URI, strong validator, durable offset, expected representation length/hash, verified-artifact state, associated staging generation, consent/version and actionable failure details. File paths and Android scheduler types stay adapter-private.

Persist jobs before scheduling. Use an Android durable scheduler/foreground integration appropriate to target SDK, with notifications and real cancel/pause actions; verify API23/API36 and 16 KiB compatibility. Process death leaves a recoverable persisted job. User cancel never auto-restarts; pause preserves the partial file; resume rechecks current consent, Wi-Fi policy and disk space. Restoring preferences/jobs cannot itself authorize downloads.

For resume use representation-stable raw artifact bytes, strong ETag with Range/If-Range, validated 206 Content-Range start/total and unchanged final URI/encoding. A 200 response, weak/missing validator, changed metadata, invalid range or redirect change invalidates append and requires a clean retry under the manifest/consent policy. Handle 416 only after independently proving the artifact complete. Account for transparent HTTP decompression: compressed-file resume and decoded-byte offsets must never be mixed.

Write/flush durable bytes before advancing persisted offset; after a crash truncate uncheckpointed tail, and invalidate an offset beyond actual file length. Hash the complete artifact again after resumed acquisition; do not pretend MessageDigest state survives restart. An atomically published verified artifact may then be reimported from byte zero after process death. This is the smallest correct gzip recovery design: download resumes durably; import restarts locally from the retained complete artifact without redownloading. Expose that distinction in status. Arbitrary compressed or JSON-array byte offsets are not safe parser checkpoints.

### 3. Additive storage and safe activation

Orchestrator owns reviewed schema changes despite the physical files currently residing under `data/storage/.../schema`; no `android-app/database/registry` exists yet. Add a real generated next schema and migration from v2, retaining all v1/v2 rows and no destructive fallback.

Minimum additions: `download_job` plus private artifact/checkpoint metadata; generation verification/coverage/format/budget version fields; a generation-keyed ruling table and ruling coverage metadata; generation-keyed typed search/legality/finish projections with indexes. Record missing versus verified-empty ruling coverage. Ruling IDs use provider ID or documented deterministic oracle/date/source/text identity; retain source date versus retrieval date and provenance. Expose bounded `CatalogRulings.lookup(OracleId, PageRequest, CancelToken)` plus lookup/status ports for card and printings. Full offline card details must show real retained rulings; comprehensive rules text is a separate corpus.

Rulings may be a separately staged dataset with its own generation/pointer and explicit compatibility/coverage relation to the card generation. If UI offers one atomic “full English catalog + rulings” update, activate a bundle manifest referencing both validated generations in one transaction; never show overall completion after only cards succeeded. Preserve unresolved ruling oracle references for reconciliation, not guessed name matches or silent dropping. Lean mode retains previously fetched rulings and user data.

Projection fields include exact nullable mana value/stat representations, color/identity masks, types/keywords, layout, legality by all source formats, printing set/language/finish and face semantics. Preserve symbolic stats; unknown is not numeric zero. Use deterministic versioned projections, parameterized AST queries and indexes; update them in the same staging batches as source rows. Do not parse every raw JSON payload during full-table search. Reuse canonical FTS where suitable; extend text/face indexing once per canonical record without printing fan-out. Bind bounded cursors to generation/query/order and reject stale generations. Retain source-provided printings without oracle IDs as explicitly unresolved if encountered; the current mapper requiring `oracle_id` must not silently discard valid corpus entities.

Recovery classifies generations by durable owning job. Never delete resumable staging merely because its state says STAGING. The simple restart-import path marks the old stage abandoned, starts a new generation, and performs bounded deferred deletion. Avoid blocking all reads/status on full stale-generation cleanup. Final validation checks expected counts/coverage, foreign keys/identity conflicts, rules/rulings relationships and projection/FTS consistency; then atomically compare/update active pointers and mark the job completed. A database lease/revision prevents duplicate workers or stale activation, not just the process-local Mutex. Cancel before commit retains the previous pointer; cancel racing after durable commit cannot claim the catalog was undone. Rollback/disk-full/corruption never clears the active catalog or user tables. GC retired generations only when no pinned readers/snapshots need them.

Preflight space must include existing active DB, new staging/indexes, artifact/partial artifact, journal/WAL and headroom; recheck while writing and fail truthfully on ENOSPC. No user tables are cascade children of a refresh generation.

### Network worker may start against existing merged ports

Root selected `HttpURLConnection`, avoiding an unverified new HTTP dependency. Isolate `:data:network` implementation/tests; root owns Gradle settings, dependency registry, manifest INTERNET permission and DI integration. Android library with JVM local `HttpServer` tests is suitable, supplemented by real Android cancellation/TLS behavior. `Clock`/delay injection allows deterministic monotonic limiter/backoff tests.

- Turn off automatic redirects and caches; validate initial origin and every explicit redirect, cap redirects, and apply production HTTPS policy. Loopback HTTP is a deliberate test configuration. Verify HTTP header name/value syntax in the adapter; current `HttpHeader` name validation omits CR. Never retain credentials or URLs containing secrets in logs.
- Network cannot read vault through an undeclared dependency. Until a genuine auth resolver exists, reject non-null `EndpointProfile.secret` with typed unavailable; do not silently ignore it. An authorized higher-level caller may supply already resolved scoped headers under a documented boundary. Reject unsupported semantics explicitly.
- Metadata must arrive with first chunk (including an empty terminal chunk for an empty response), contiguous sequence/offset starts at zero per invocation, final is emitted once only after true EOF, and truncation emits failure with no fake final success. Document HTTP status handling; acquisition accepts only validated success statuses, including explicitly checked 206, never a downloaded error body.
- `maxResponseBytes` is the documented raw representation bound. Request `Accept-Encoding: identity` by default and do not silently decode gzip. A caller deliberately acquiring a compressed artifact owns its content encoding/representation metadata. Use fixed-size read buffers, bounded buffered `send`, and close response/error streams and disconnect on every exit.
- Safe GET/HEAD retries only before streaming bytes escape; no hidden replay after an emitted chunk. Preserve caller charge/retry constraints, obey Retry-After within total retry policy and expose exhausted failure. Rate limits must be shared by source/origin rather than bypassed by constructing another profile ID.
- Blocking `read()` must be actively disconnected on coroutine cancellation; finite timeouts alone do not establish <=1 second. `CancelToken` has no cancellation callback, so plan a bounded observation mechanism for token-only cancellation too. Own any monitor in the caller's structured scope. `close()` is idempotent, aborts active calls and rejects later calls. Do not turn CancellationException into a typed transport error.
- Tests: exact cap/over-cap, unknown length/truncated body, empty success, redirects/loops/origin credential leakage, safe retry versus already-emitted bytes, Retry-After/rate limiting, connect/read and token-only cancellation, malformed status/header handling, close during active stream, and no raw secrets in diagnostics.

This transport work does not depend on deciding the English bulk source. Durable jobs, source approval and full import still remain required before download controls can report completion.
