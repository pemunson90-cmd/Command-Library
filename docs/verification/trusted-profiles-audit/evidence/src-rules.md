## Discrepancies
- docs/verification/k3-downloads/PERSONAL-SOURCE-REVIEW.md:49 says the existing genuine local bytes 'start “These rules are effective as of September 25, 2026”'. The actual file starts with the title 'Magic: The Gathering Comprehensive Rules' (line 1), then an NBSP-only line (line 2); the effective-date sentence is line 3. The sentence is correct, but 'start' is imprecise, which matters for a first-bytes sanity check.
- The R-03 proposed subrule regex ^(\d{3})(?:\.(\d+)([a-km-np-z])?)?\.?\s+ (R-03-comprehensive-rules.md:68) and the Kotlin SUBRULE regex ([a-z], RulesStructure.kt:359) both allow exactly one suffix letter. The CR has a two-letter subrule, 704.5aa (CR line 5561), which is silently treated as continuation of 704.5z by the Kotlin parser. The recorded '0anomalies' evidence in coordination/state.json:36 would not reveal this.
- R-03 (docs/gauntlet/research/R-03-comprehensive-rules.md) says 'Do not confuse the connector's 8,017 rendered TXT lines with original bytes or physical line count'. The physical file has 9,372 LF-terminated lines, with 4,094 NBSP-only lines. This agrees with the caution, but any parser line-count assertion must use the 9,372 figure.
- The task text and repo use the %20-encoded TXT URL. The official page's href contains a raw space: 'MagicCompRules 20260925.txt'. The URLs are equivalent only after encoding. A scraper that stores the raw href would store a URL that is not valid unencoded.
- HTTP Last-Modified (2026-08-17T16:18:07Z, consistent with the 2026-10-13 recorded figure) differs from the ETag's embedded epoch (2026-09-18T16:30:22Z) and from the in-text effective date (2026-09-25). The repo is right not to treat Last-Modified as the effective date, but it is also not a reliable store-time signal.
- The Fan Content Policy refers to 'the restrictions listed in #3', but the restrictions are in item 4 ('Don’t hurt Wizards'). This is a minor internal inconsistency in the vendor text. Item numbers should be cited by heading, not by number.
