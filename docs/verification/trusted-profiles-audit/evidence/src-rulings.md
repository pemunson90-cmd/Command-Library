## Discrepancies
- Task/prompt expected fields download_uri, size, content_type, content_encoding on the bulk object. The real object has only jsonl_download_uri and compressed_size (9 keys total); no content type/encoding or checksum is advertised in metadata.
- bulk_data.description (and the docs table) says 'A JSON file containing all Rulings', but the file is gzipped JSON Lines (.jsonl.gz). The docs prose says JSONL, so the description string is stale and must not be used to pick a parser.
- Docs say 'daily exports' and 'URLs ... change their timestamp each day', but observed filenames and Last-Modified values show regeneration roughly every 12 h (about 09:00 and 21:00 UTC).
- Docs size column says 'MB' but the values are MiB (5,422,271 / 1,048,576 = 5.17).
- updated_at, URL, ETag and Last-Modified rotate every ~12 h while compressed size (5,422,271) and the 64 KiB prefix (305,885 decoded bytes, 918 lines) are identical across the dated files compared. Freshness metadata is not a content-change signal.
- Accept-Ranges appears on the 200 HEAD but not on the 206 Range response; harmless, but do not rely on the header in the 206 to detect range support.
- Repo OkHttpNetworkClient.kt:366 throttles '/bulk-data' at 6 s, while the docs' 6,000 ms limit applies only to /cards/manifest and /bulk-data is under 'All other methods' (10/s).
- Docs require User-Agent and Accept headers only for api.scryfall.com; the docs say nothing for data.scryfall.io, which has no rate limits ('*.scryfall.io').
- The /docs/api page contains agent-directed text (a 'honeypot' email instruction). It was treated as untrusted content and not acted upon.
- Plan deviation: one extra HEAD (rulings-20261010210033) was used to probe retention, bringing data.scryfall.io requests to the stated cap of 4. A second Range GET of a superseded file to prove byte-identity was deliberately not made (would exceed the single-bounded-GET instruction).
