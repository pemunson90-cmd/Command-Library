## Finding requiring a small private fix

**F1 — token cancellation can finish as success within one chunk.** In `Utf8LineReader.kt` at code SHA `796c665`, `readUtf8Lines` calls `cancel.throwIfCancelled()` only at the start of each `chunks.collect` iteration. `LineAssembler.accept` processes all decoded lines in that chunk; its every-256-lines check calls only `ensureActive()` on the coroutine. `LineAssembler.finish()` also emits a final unterminated line without checking the token afterward. If an `onEntry` callback marks a `CancelToken` cancelled while processing a single final chunk, the parser may emit later entries and return `Ok` with a valid hash despite cancellation. The existing countdown test uses 16-byte chunks, so it does not exercise this case. Minimal fix: pass the token to `LineAssembler`, check it before/after line callbacks (including `finish`), and check it before returning the digest; add a one-final-chunk synthetic test where the callback cancels the token after the first entry and assert `CancellationException`, never `Ok`. Keep coroutine cancellation checks too.
