## Nonblocking clarifications

G2-R03, moderate: SPEC B06 and DATA_MODEL FormatDefinition say every format exposed by the source, while Appendix A answer 9 says all formats. This is not evidence of a deliberate cut, because the title and validation contract retain all-format intent and unknown/review states. Still, add a supported format-registry inventory and explicit handling for a format absent from card-source legality fields, especially limited/custom/team variant rules. Separate data legality, deterministic deck constraints and manual checks. Do not let source-field absence silently delete a format selector or claim a clean legality pass. Exact current source facts can remain evidence follow-up.

G2-R04, moderate: PERFORMANCE P06 excludes pinned decoded art from the memory ceiling. P12 bounds image disk cache, which does not bound decoded images in RAM. Add a finite decoded-image working-set budget and report total process RSS with the art scenario, separately reporting loaded LLM overhead. Pinned offline image files need not be pinned decoded images. Otherwise a graphics-heavy deck/life layout can evade the concrete base-app memory ceiling. This is a budget clarification, not a claim that the proposed numbers have failed.

G2-R05, minor trace accuracy: several existing parity-family links rely unnecessarily on umbrella IDs. Examples: PX05-022 hypergeometric -> B04, PX05-061 set browsing -> A07/A08, PX05-063 rulings -> A04, PX06-062 recommendations -> D02, PX07-009 opposing commander damage -> G03, PX07-027/028 random tools -> G06, PX07-029 turns -> G07, PX07-037 resume -> G10, PX07-081 full backup -> I02.
