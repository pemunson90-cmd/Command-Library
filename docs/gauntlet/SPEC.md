# SPEC: Command Library

Gate 2 specification draft. Flutter selected by D-07. All six Gate 1 rulings applied; D-14 is English default with explicit approval for other-language downloads. This document describes required behavior and future acceptance, not implemented features or measurements.

## Authority and completeness

Latest Pat rulings in DECISIONS outrank this specification; GAUNTLET_CODEX sections2/3 and Appendix A provide the baseline. Gate 1 topic reports and approved full parity matrices add scope; competitor UNVERIFIED evidence never cuts required behavior. English filtering applies to automatic language data transfer, not destruction of a foreign owned identity. Full offline rules remain mandatory. Do not narrow personal functionality to resolve public-release concerns.

Every requirement below has an ID, primary component, screen and observable acceptance. COVERAGE maps baseline and each parity row. Supplementary contracts: DATA_MODEL, COMPONENTS, SCREENS, PERFORMANCE and DESIGN_SYSTEM. Gate 3 turns them into exclusive-path ARCHITECT documents, pinned dependencies and milestone steps before code.

## User paths and delivery rules

1. First run selects Full English by default, shows current size estimate, obtains base-download confirmation and separately offers optional packs. Interrupted downloads resume; text functionality can begin with validated imported data.
2. Search/detail remains useful offline; local results identify active corpus coverage. Unsupported query can invoke a separately labeled online action.
3. Create/import a deck, organize/edit, inspect validation/analysis/brackets, own cards and calculate missing acquisition cost; suggestions never replace deterministic validation.
4. Start an offline1-6 player game, persist counters/timers/events and associate deck results.
5. AI uses direct user keys, local/LAN, on-device or prompt export; all responses validate locally. No provider/key is needed for prompt export or the rest of the app.
6. Backup/restore is previewed and atomic; no credential or optional download is silently reactivated.

No unfinished destination/control may ship. Early milestones expose only actual implemented user paths. Every build/adapt parity row is required by final completion; optional means user-enabled, not unimplemented.

## Pricing semantics and durable state contracts

Currency amounts use decimal fixed precision with explicit currency or TIX unit. For a contextual demand q, allocated compatible owned quantity o, and unit acquisition quote p, default n = max(q-o,0)*p. If missing quantity is zero, n is zero regardless of absent quote; otherwise absent quote yields unknown. Totals preserve unknown counts, not invented zeros. Market value is q*p and remains separate from acquisition; selected provider statistic/finish/date never hidden. Any-printing allocation never consumes the same physical copy twice within one deck and pinning opts into strict identity; grouping by category does not create a second demand. Portfolio/several-deck costs are independent what-if estimates unless explicitly reserved; no phantom global reservation.

User edits are committed transactionally and independently of refreshable catalog generations. Autosave debounces text to at most500ms, flushes on deliberate navigation/background when possible and surfaces failures; committed data must survive process death. Uncommitted text draft recovery is stored separately and disclosed. Long operations expose phase/progress/pause/cancel; state snapshots are immutable inputs to analysis and UI. Async results must match current deck/generation/version before replacing display.

## Cross-feature empty/error/offline states

Every screen uses defined loading/empty/partial/offline/stale/error/disabled states in DESIGN_SYSTEM and SCREENS. Empty means genuinely no data, never dummy content. Unknown rules/price/ID/intent are explicit and do not count as valid/affordable/official evidence. Errors retain user input and give one useful recovery action. Downloads never report success before hash/schema/index validation and activation. Background failures never delete user data or credentials.

## Evidence follow-up before verified release claims

See COVERAGE E01-E13: current source terms/bytes/coverage, Game Changer set reconciliation, authentic vendor fixtures, provider schemas/eligibility, stable Flutter bridge/engine settings, device accessibility/model performance and signed package installation. These are required verification tasks, not generic reasons to omit features. Runtime measurements occur after authorized architecture/implementation; Gate2 writes no app spike.

## Acceptance reporting

For each delivered requirement, record fixture/source version, build SHA, platform/window/posture, assertion result and material limitations. Unit tests cover domain math/state/parsers; DB tests cover FTS/index/migration/import/restore failures; UI smoke and screenshot audit cover real tasks; physical reader/fold checks have separately identified evidence. A milestone cannot call a failed or unrun requirement passed.

## Local query semantics

Implement documented local aliases name, o/oracle, t/type, c/color, id/identity, mv/cmc, pow/power, tou/toughness, loyalty, defense, legal/format, rarity, set, lang/language, finish, keyword, layout, is:reserved, is:gamechanger, owned, in:deck and price against held fields.
