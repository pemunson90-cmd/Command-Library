# R-13 Adaptive layouts, foldables, Windows desktop UX

Path: `docs/gauntlet/research/R-13-adaptive-layouts.md`. Task card: `coordination/tasks/cc-research-13.md`. Author: researcher (Sonnet). Access date for every source below is 2026-10-11 unless stated. Anything not confirmed by a source is marked UNVERIFIED.

STATUS: draft in progress (sections are added in passes; the last line of the file is a completion marker when finished).

## Question

How does each candidate stack (S1 Kotlin Multiplatform + Compose Multiplatform, S2 Flutter, S3 .NET MAUI, S4 Avalonia, S5 React Native + React Native for Windows, S6 Tauri 2) support window size classes, list-detail and supporting-pane layouts, foldable postures, and Windows desktop interaction and accessibility? This feeds GAUNTLET.md 2.J, 2.G (tabletop posture) and the R-01 adaptive and accessibility criteria.

## Findings

### F1. Window size classes (Android developer docs)

- Width classes: compact < 600dp; medium 600dp to < 840dp; expanded 840dp to < 1200dp; large 1200dp to < 1600dp; extra-large >= 1600dp. Source: https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes (accessed 2026-10-11; page says "Last updated 2026-09-22 UTC").
- Height classes: compact < 480dp; medium 480dp to < 900dp; expanded >= 900dp. Source: same URL.
- Large and extra-large were added beyond the three Material classes "to better target desktop and connected displays". They are opt-in: `currentWindowAdaptiveInfo(supportLargeAndXLargeWidth = true).windowSizeClass`. Source: same URL. The fold-aware page states `currentWindowAdaptiveInfoV2()` returns the size class "with large and extra-large breakpoints by default": https://developer.android.com/develop/ui/compose/layouts/adaptive/foldables/make-your-app-fold-aware (accessed 2026-10-11).
- Docs guidance: width is usually the primary factor; consider height for phones or open flippables in landscape (width medium, height compact, so two-pane is impractical); do not use size classes as `isTablet` logic; the class can change at runtime with rotation, multitasking or folding; design for expanded first, then decide a specialized medium layout. Source: use-window-size-classes URL above.
- API: `androidx.window.core.layout.WindowSizeClass`, `currentWindowAdaptiveInfo()` returning `WindowAdaptiveInfo`, `WindowAdaptiveInfo.windowSizeClass`, `isHeightAtLeastBreakpoint(...)`, `WindowSizeClass.HEIGHT_DP_MEDIUM_LOWER_BOUND`. Source: same URL.
- Consequence for GAUNTLET.md 2.J: the three-class mapping in 2.J (compact, medium, expanded) matches the Material definitions but omits large and extra-large. A 1920x1080 desktop window at 100% scaling is 1920dp wide, so it is extra-large, not merely expanded. See Recommendation.

### F2. S1 Android: Material 3 adaptive libraries and versions

- Artifact group `androidx.compose.material3.adaptive` publishes `adaptive`, `adaptive-layout` (ListDetailPaneScaffold, SupportingPaneScaffold), `adaptive-navigation` (Navigable* scaffolds) and `adaptive-navigation3` (Navigation 3 scene strategies). Source: https://developer.android.com/jetpack/androidx/releases/compose-material3-adaptive (accessed 2026-10-11); `adaptive-navigation3` existence confirmed in Google Maven metadata, https://dl.google.com/dl/android/maven2/androidx/compose/material3/adaptive/adaptive-navigation3/maven-metadata.xml (accessed 2026-10-11, latest 1.4.0-alpha03, lastUpdated 2026-10-07).
- Versions: stable 1.3.0 (August 12, 2026); 1.3.0-rc01 June 17, 2026; latest alpha 1.4.0-alpha03 (October 07, 2026). 1.2.0 stable was October 22, 2025. Source: https://developer.android.com/jetpack/androidx/releases/compose-material3-adaptive (accessed 2026-10-11). Cross-check on Google Maven: the version list ends `1.3.0-rc01 1.3.0 1.4.0-alpha01 1.4.0-alpha02 1.4.0-alpha03` (https://dl.google.com/dl/android/maven2/androidx/compose/material3/adaptive/adaptive/maven-metadata.xml, accessed 2026-10-11).
- `NavigationSuiteScaffold` is a different artifact: `androidx.compose.material3:material3-adaptive-navigation-suite`, versioned with Material 3. Stable 1.4.0, latest 1.5.0-beta01 (October 07, 2026). Package `androidx.compose.material3.adaptive.navigationsuite`. Sources: https://developer.android.com/jetpack/androidx/releases/compose-material3 and https://dl.google.com/dl/android/maven2/androidx/compose/material3/material3-adaptive-navigation-suite/maven-metadata.xml (both accessed 2026-10-11).
- Notable adaptive API facts: pane expansion (user-draggable split) arrived in 1.1.0 (March 12, 2025); reflow and levitate adaptation strategies in 1.2.0 (stable October 22, 2025); `ListDetailPaneScaffold` and `SupportingPaneScaffold` support margins and edge-to-edge, and `adaptive-navigation3` shipped, in 1.3.0; `NavigableListDetailPaneScaffold` and `NavigableSupportingPaneScaffold` have default predictive back since 1.1.0. Source: https://developer.android.com/jetpack/androidx/releases/compose-material3-adaptive (accessed 2026-10-11).
- API churn to plan for: `currentWindowAdaptiveInfo` is deprecated in favor of `currentWindowAdaptiveInfoV2` (release note: "Deprecate currentWindowAdaptiveInfo and introduce V2 of it", b/424442112; the notes also list "Deprecate window size APIs"). `DragToResize` and pane margin APIs were marked experimental in 1.3.0-alpha10 (April 8, 2026). The 1.4.0-alpha01 notes remove component override APIs for `NavigationSuiteScaffold` and `ThreePaneScaffold`. Source: https://developer.android.com/jetpack/androidx/releases/compose-material3-adaptive (accessed 2026-10-11).
- Posture helper: `adaptiveInfo.windowPosture.isTabletop` via `currentWindowAdaptiveInfoV2()`, and `collectFoldingFeaturesAsState()` exposes the raw `FoldingFeature` list. The release notes say `calculatePosture()` was promoted to stable in 1.2.0-alpha07 and hidden as internal in 1.2.0-beta02. Sources: make-your-app-fold-aware page and release notes page above (accessed 2026-10-11).

### F3. S1 Compose Multiplatform (desktop): availability of the same libraries

- JetBrains republishes the adaptive libraries as `org.jetbrains.compose.material3.adaptive:adaptive`, `adaptive-layout`, `adaptive-navigation`, `adaptive-navigation3`; stable 1.3.0 (Maven Central lastUpdated 2026-10-06; version list ends `1.3.0-rc01 1.3.0`). Source: https://repo1.maven.org/maven2/org/jetbrains/compose/material3/adaptive/adaptive-layout/maven-metadata.xml and `.../adaptive-navigation3/maven-metadata.xml` (accessed 2026-10-11; streamed with curl, nothing saved).
- Targets: the `kotlin-tooling-metadata.json` of `adaptive-layout` 1.3.0 lists an Android library target, a `KotlinJvmTarget` (the target a Compose Desktop app consumes), `ios_arm64`, `ios_simulator_arm64`, a JS target and `macos_arm64`. Source: https://repo1.maven.org/maven2/org/jetbrains/compose/material3/adaptive/adaptive-layout/1.3.0/adaptive-layout-1.3.0-kotlin-tooling-metadata.json (accessed 2026-10-11; only the first 2500 bytes were read, so any later targets were not seen). So `ListDetailPaneScaffold` and `SupportingPaneScaffold` are published with a JVM target. This research did NOT run a desktop build, so "renders correctly on Windows desktop at runtime" is UNVERIFIED.
- `NavigationSuiteScaffold` for CMP lives at `org.jetbrains.compose.material3:material3-adaptive-navigation-suite`. Maven Central lists only alpha versions (up to `1.12.0-alpha03`, `1.13.0-alpha01`, `1.13.0-alpha02`); no stable. Its `1.12.0-alpha03` tooling metadata lists Android, JVM, iOS, JS, macOS and wasm targets. Sources: https://repo1.maven.org/maven2/org/jetbrains/compose/material3/material3-adaptive-navigation-suite/maven-metadata.xml and `.../1.12.0-alpha03/material3-adaptive-navigation-suite-1.12.0-alpha03-kotlin-tooling-metadata.json` (accessed 2026-10-11).
- `org.jetbrains.compose.material3:material3` stable versions on Maven Central end at `1.9.0`; every later version is alpha (latest `1.13.0-alpha02`). Source: https://repo1.maven.org/maven2/org/jetbrains/compose/material3/material3/maven-metadata.xml (accessed 2026-10-11). The CMP 1.12.1 release (published "22 Sep", year not shown on the GitHub page) bundles `org.jetbrains.compose.material3:material3*:1.12.0-alpha03` (mirrors Jetpack Material3 1.5.0-alpha22), `org.jetbrains.compose.material3.adaptive:adaptive*:1.3.0-rc01` (mirrors Jetpack adaptive 1.3.0), Navigation `2.10.0-beta01`, Lifecycle `2.11.0`, `org.jetbrains.androidx.window:window-core:1.5.1`. Source: https://github.com/JetBrains/compose-multiplatform/releases/tag/v1.12.1 (accessed 2026-10-11). Consequence: an S1 desktop UI would sit on a Material 3 build JetBrains labels alpha, while Jetpack Material3 1.5.0 is itself only at beta01 (Jetpack stable is 1.4.0).
- CMP latest stable Gradle plugin is `1.12.1`; `1.13.0-alpha02` is the newest pre-release. Source: https://repo1.maven.org/maven2/org/jetbrains/compose/compose-gradle-plugin/maven-metadata.xml (accessed 2026-10-11). The CMP compatibility page lists 1.12.1 as the latest release (maps to Jetpack Compose 1.12.1): https://kotlinlang.org/docs/multiplatform/compose-compatibility-and-versioning.html (accessed 2026-10-11).
- Window size classes in common code: the JetBrains doc uses `org.jetbrains.compose.material3.adaptive:adaptive` with `androidx.window.core.layout.WindowSizeClass` and `currentWindowAdaptiveInfoV2` from `commonMain`. Source: https://kotlinlang.org/docs/multiplatform/compose-adaptive-layouts.html (accessed 2026-10-11). The page's dependency line is `1.3.0-rc01`; it does not list platform support and does not mention the pane scaffolds. Whether `currentWindowAdaptiveInfoV2` on desktop tracks live window resize in dp: UNVERIFIED (not stated on the page; not built).
- Jetpack WindowManager posture and hinge APIs (`FoldingFeature`, `WindowInfoTracker`) are Android-only. CMP republishes only `window-core` (`org.jetbrains.androidx.window:window-core:1.5.1`), which holds `WindowSizeClass`. Source: https://github.com/JetBrains/compose-multiplatform/releases/tag/v1.12.1 (accessed 2026-10-11). That a desktop `windowPosture` is always "not folded": UNVERIFIED (source not read).
