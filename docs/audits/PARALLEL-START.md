## Claims and completion

Use existing canonical fields/status vocabulary. The following semantics are mandatory even if the repository spells states differently:

- READY: prerequisites and acceptance outcome are known; no conflicting owner.
- TAKEN: named owner/session, exact base SHA, branch/worktree, allowed paths, consumed interface versions, expected outcome, verification command and handoff location are recorded before work begins.
- REVIEW: returned source is frozen; root verifies allowed-path diff and prerequisites; this is not completion.
- FINISHED: accepted source is integrated or explicitly accepted as a standalone deliverable, required scoped checks passed, exact SHA/evidence is linked and claims are released.
- BLOCKED: precise dependency/failure and unblock action are recorded; independent ready work proceeds.
- SUPERSEDED: successor and reason are linked; preserve original evidence.

Distinguish producer completion, app integration and requirement acceptance. Host tests do not establish native/physical completion. A worker return or successful compile alone cannot finish a user journey. Never claim a task already TAKEN; do not reset another actor's status based on old timestamps.

## Failure checks and loop containment

Before a costly run check toolchain/access, target source SHA, dependencies, existing artifacts and whether the needed test already ran on identical relevant source. Reuse evidence only with explicit source equivalence and matching scope.

For failure record: command, source SHA, category, failing assertion/error, hypothesis, smallest discriminating probe and result. Distinguish environment/network/fixture/product failures. Never change a valid assertion solely to turn a test green.

Do not repeat an identical failed action without new evidence or a changed relevant condition. After two repair attempts without progress, stop that approach and perform a root-cause review or independent review. Continue other ready work; unblock only with a new concrete hypothesis. Do not interpret this bound as permission to abandon the task silently.

Research recursion defaults to three levels. Each child uncertainty must change an engineering decision or acceptance test. Stop when actionable, executable or concretely blocked. Preserve exact access failure and a permitted alternative; no repeated forbidden-host retries. Later-feature research does not gate the core release.

On token/time pressure, reserve enough capacity to publish a recoverable handoff. Do not begin a dependency-spanning change that cannot leave a safe checkpoint. No artificial per-edit full-suite ritual: focused verification during work, broader checks at meaningful integration/risk boundaries.
