# Modern life semantic actions and initialization

Status: concrete proposed design for root-owned cx-m2-life-action-engine-01; no implementation acceptance yet. Existing reviewed persistence design/dispositions and SPEC G01–G14/PX07 remain requirements. Timing/source/storage authority stays distinct. No schema/DI/UI change assumed. Inline execution continues under user authorization.

## Ordered bounded units

1. Counter action semantics, reusing CounterReducer rather than duplicating slot/bounds/loss logic: exact numeric SetCounter, adjustment-step/deduction preferences, add/update definitions, explicit damage/life groups and ON_TURN_START resets. Pure result preserves revision/event pointers and returns canonical logged actions plus loss candidates. Does not settle time itself; later action orchestrator does so once per observation.
2. Participation/designations/presentation/ack semantics: explicit confirmed eliminate/restore and observed-candidate dismissal; retain counters and immutable roster, no inferred results. Pause a running seat countdown when its owner is eliminated; pause elapsed if its turn owner is eliminated, retaining assignment for explicit later switch/resume. Restore does not resume timers. Preserve existing designations unless explicitly edited; new holder/blessing targets must be active seats. No automatic rules transfer inferred from elimination. Acknowledgment is monotonic operational history; undo must carry it forward.
3. Result semantics: explicit full-roster WIN/LOSS/DRAW outcomes; legacy Finish maps empty winners to draw and nonempty winners to winners/other losses without inventing exit reasons. Settle/pause both ledgers; one stable result ID across finish/retract/refinish. Reopen retains balances and pauses, never charges completion gap. Undo semantic restoration composes reviewed timing patch and preserves current alert/result operational lineage.
4. Actual initialization: fresh GameId and Known opening turn lineage from caller; revision0, no event/result/designations/alerts, turn0/no owner, all timers paused and no anchors, game/turn elapsed0. Preserve seats/slots/decks/profile/source Knowledge exactly; explicit initial counter states match defined scope (seat, own tax slots, opposing damage slots; absent stolen-own damage remains legitimate implicit initial state). Variant initialization is a separate trusted data-driven backend: current VariantDefinition does NOT identify initial zone/phase/placement policy, so never guess a deck zone from labels or emit empty variant states as success. Document and review the exact typed manifest/backend gap before implementing variant setup. Variant-free initialization is a real bounded helper, not optional-variant completion.
5. Random resolution/replay and variant semantics: retain accepted batch10000/no dropped remainder, request/batch identity and active-only eligibility, recorded replay without draws; reject mixed random groups per existing design. Variant source/rights/initialization/rule transitions need actual versioned inputs; generic state validation alone is insufficient. Do not register a service with unsupported retained baseline families.
6. Pure action/event orchestration: one GameTimeObservation, flat group1..1024 with at most one SwitchTurn, one final atomic archive/checkpoint. Root service provides allocated event/group/result/lineage identity and authoritative current/target archives. Settle current before actions, preserve immutable action-time before/after, canonical flat logged action, final graph validation and result revision coherence. Transactional storage remains sole commit/CAS authority. The service/observe/history/publication/OS/UI packets follow, not implied by pure action helpers.

## First counter unit: concrete API and semantics

Internal LifeCounterEngine.reduce(snapshot, action) -> Outcome<CounterReduction>. Derive CounterRoles only from SnapshotGraphValidator. Handle AdjustCounter/SetCounterHidden using the exact existing reducer. For SetCounter, look up current explicit or implicit initial value, calculate target-current in Long; reject zero or delta outside Int range, then delegate canonical AdjustCounter, independent of adjustmentStep. An invalid slot/seat/definition is rejected by existing reducer. Canonical action carries exact checked delta for the event log, including within flat counter-only groups. Nested/empty groups rejected; whole group is pure all-or-nothing. Elimination is never automatic; callers present returned candidates.

SetAdjustmentStep and SetCommanderLifeDeduction update only preferences (positive step already typed). AddCounterDefinition requires new ID and OTHER role, maximum128 definitions. Update requires existing same ID and same role; LIFE.initial must still equal settings.initialLife. Validate all recorded values against new bounds via the existing graph guard; implicit values follow updated initial. Never delete definitions, relabel roles, coerce/clamp values, or infer poison semantics from preset labels. Retain every hidden state. Preference/definition changes report candidates based on final state; newlyReached compares stable (definition,seat,slot) candidate membership under OLD definitions/policies before vs FINAL definitions/policies after; already-met to already-met is not new even if the policy changed. Display text never defines identity. Candidate membership includes implicit initial values as accepted reducer requires.

Commander damage helper returns an explicit existing flat Group using settings.deductLifeForCommanderDamage and existing CounterReducer.commanderDamage. Raw AdjustCounter/SetCounter remain literal edits; canonical groups are never implicitly expanded again, preventing double life subtraction. The later UI's commander-damage control calls this helper; exact numeric corrections remain explicit. Validate group ID without generating hidden IDs.

resetForTurn(snapshot, incomingSeat) resets only all explicit ON_TURN_START counter states across every seat and commander slot to definition.initial, preserving hidden flags/slot identity; missing states already mean initial and need no synthetic state. It returns Outcome<GameSnapshot> and does not increment turn, refill clocks or change revision. Reset assigns initial directly and need not fit an AdjustCounter Int delta; incomingSeat is validated as active context, never used to scope reset. Called exactly once for SwitchTurn by the later orchestrator, never by PassClock; reset is part of same action provenance so undo restores all affected values. Definitions/role validation applies before and after.

Counter helpers do not validate source-backed rule authority, resolve random/variant actions, create result IDs or accept completed-game mutations. No partial GameService registration. Pure input identity/graph failures stay typed, with invalid new definition/bounds requests INVALID_INPUT rather than presenting malformed proposed state as stored corruption.
