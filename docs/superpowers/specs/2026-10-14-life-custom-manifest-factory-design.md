## Pinned policy-v1 DTO/framing and validation order

Public DTO names/fields/defaults: CustomVariantManifest(definition,initialState,transitions); CustomVariantSelection.None, Top(count), Explicit(minimum,maximum), Shuffle; CustomVariantInsertion.TOP/BOTTOM; CustomVariantTransition(actionId,phases,fromZone,toZone,selection=None,insertion=BOTTOM,appendDrawn=false,appendDiscarded=false,nextPhase=null,properties=empty,reset=false). Internal manager gets a pure internal configuration validation method, never a fabricated GameCreation just to run setup.

Reserved key is 'command-library.custom-policy-v1', forbidden in caller initial properties and literal replacements regardless of value subtype. Computed value 'sha256:' plus64lowercasehex. Canonical byte sequence: length-prefixed strictUTF8 header 'command-library/custom-policy/1'; definition ProviderIdentity+version; initial VariantState; ordered transition list. Identity encodes provider.value/kind/rawId strings in that order. String has signed big-endian Int32 nonnegative byte length then exactUTF8 bytes, nullable string has byte0(absent) or1(present)+string; no normalization. Boolean byte0/1; Int32/Int64 fixed big-endian. Lists Int32 count then ordered elements.

State order: definitionId,version,zones(zoneId,cardIds),drawn,discarded,phase,properties,seed,actionCounts(actionId,count). Property order key then value tag (Text0+string,Integer1+Int64,Flag2+bool,Card3+identity). Transition order actionId,phases,fromZone,toZone,selection tag(None0,Top1+Int32,Explicit2+min/maxInt32,Shuffle3),insertion tag(TOP0,BOTTOM1),appendDrawn,appendDiscarded,nextPhase,properties,reset. All options included even inactive/default; initial marker absent during digest. Exact authored list order is identity-significant and preserved. Never change this framing under key v1; later policy framing needs a distinct key/version and deliberate retained-reader policy.
