## Outcome and boundaries

Separately disclose/persist raw invalid editor input, then commit eligible text deltas after at most500ms scheduling debounce, with maximum-wait during continuous input and immediate deliberate-navigation/background flush when possible. This is a scheduling limit, not a guaranteed disk-completion latency. Surface failures; committed content survives reopen; native process-death/lifecycle/device evidence remains distinct. Never claim raw recovery means deck saved.

Each nonempty batch remains one ordinary undo group under LocalDeckEdits. No rewriting/coalescing historical links. Empty semantic deltas create no content revision/group. Autosave only eligible existing DETAILS and ENTRY text. ADD and REMOVE remain explicitly confirmed, never inferred from form validity/default quantity1. New/duplicate-name forms remain explicit workflows, outside this boundary. Recover raw ADD text without trusting stale selected-card proof; after an acknowledged ADD transition to stable created entry, never allocate a second entry on later text changes.

## Complete segregated capability: root-selected explicit preparation

Root chooses five methods after complementary independent architecture recommendations. Exact Kotlin source still requires contract review before implementation:

- load(id,cancel) → DeckDraftState.
- write(id,expectedGeneration,body,cancel) → DeckDraftState.
- prepare(id,token,scope,patch,operationId,cancel) → DeckDraftPreparation.
- commit(id,operationId,preparedRequestSha256,cancel) → DeckDraftCommitAck.
- discard(id,expectedGeneration,expectedPendingOperationId?,mode,cancel) → DeckDraftState.

All suspend/Outcome, existing immutable models/CancelToken. Raw input persistence and prepared authorization are separate. One qualified-deck slot, monotonic nonnegative Long generation distinct from deck Revision; absent initial slot generation0. Generation retained after discard/consume/recreation, overflow fails atomically. No clock/random IDs for raw saves. Token contains deckId,generation,baseRevision,rawSha256; raw digest excludes intent/completion metadata (no self-reference).

DeckDraftState contains generation, optional SavedDeckDraft(token,body), and latestPreparation including terminal status. This allows restart to discover both PREPARED and commit-with-lost-ack COMMITTED; not merely a pointer cleared on commit. Latest intent never substitutes for a caller's known operation ID. DeckDraftPreparation contains immutable PreparedDeckDraft(operationId,deckId,sourceToken,scope,exactPatch,requestSha256), status PREPARED/COMMITTED/ABANDONED, and acknowledgement only when COMMITTED.

Raw body references immutable same-deck baseRevision. It represents existing form mode DETAILS/ENTRY/ADD/REMOVE, targetEntryId when applicable, raw name/description/primer/quantity/notes, staged board/Knowledge finish/ordered labels, and optional ADD selected CardIdentity plus GenerationId. It does not persist CardRecord/search-membership as reusable authorization. DETAILS acts on name/description/primer; ENTRY target quantity/notes with staged choices; ADD raw text/staged selection recoverable but incomplete selection is not committable. REMOVE has no text autopromotion. New/duplicate-name forms remain separate explicit workflows.

Write CAS-saves exact raw input, including invalid content, without deck mutation/epoch. Newer raw generation may coexist with a prepared older request; write neither overwrites nor abandons that request. Preparation pins its own immutable raw bytes. Only one unresolved prepared request per deck; a second distinct prepare conflicts until resolution or explicit abandonment. PREPARED,COMMITTED andABANDONED operation IDs remain permanently reserved across every deck capability. Distinct preparation source generations strictly increase; validate latest-discovery pointer against indexed newest source generation and immutable intent association, not merely a valid FK. Immediate repeated raw write/discard verifies its stored raw-mutation fingerprint and proven resulting generation with no intervening raw mutation, then returns CURRENT DeckDraftState/status at that raw generation. It never manufactures an old latestPreparation: prepare/PreservedLater completion can change intent metadata without advancing raw generation. After raw supersession return conflict. Invalid/oversize input never truncates/replaces last durable recovery.

prepare first reconciles operation identity, then CASes exact current token, derives allowed canonical CLDP from raw/base/scope, compares exact submitted patch and durably pins source bytes/token, scope, patch and request hash in a separate immutable intent. ADD's one frozen entry ID is inside patch. Preparation does not consume raw generation or mutate deck. Repeated identical prepare returns same preparation/status before mutable head/slot validation; conflicting operation reuse INVALID_INPUT.

Scopes TEXT_AUTOSAVE and EXPLICIT_CONFIRMED. TEXT_AUTOSAVE admits only actual changed DETAILS fields and ENTRY quantity/notes, replacing from exact base entry so staged board/finish/labels are not overwritten. Explicit scope admits relevant confirmed staged/add/remove changes. ADD/REMOVE require explicit consumer intent; valid form/default quantity is never authority. Consumer revalidates ADD through existing currentDeckCard/current catalog evidence before new preparation and fresh submission, retaining raw on failure; it does not trust recovered selection. Storage independently validates identity/derived patch, not nonexistent catalog+inventory transactional authorization. COMMITTED discovery/replay bypasses fresh catalog checks. A restarted PREPARED record is not proof of earlier submission: before a fresh attempt require current selection/catalog evidence; failure preserves raw and preparation. A live owner retaining its exact already-submitted uncertain request may reconcile without fresh catalog checks. No fresh operation is inferred from recovered raw selection. Root must verify this consumer fence under restart and generation races; no atomic catalog-generation-plus-deck guarantee is claimed.

Commit accepts only opId+preparedHash, never a newly reconstructed patch. Validate prepared integrity and exact committed receipt before mutable slot/head/consumer evidence; ABANDONED cannot publish content. Fresh commit uses pinned raw/base/patch, current head==base==highest retained revision, normal package restrictions/undo, and explicit allowed scope. Its atomic slot effect is:

- Current token equals source: advance generation and clear represented input or retain derived residual staged choices based on result revision.
- Current token is later: leave raw bytes/base/generation entirely untouched; clear only resolved pending linkage and record PreservedLater(observedToken). Never silently rebase another generation.

DeckDraftCommitAck contains operationId,preparedHash,historicalSnapshot,sourceToken and immutable effect Cleared(resultGeneration), Residual(resultToken), or PreservedLater(observedToken). Return tokens, not residual raw payload. Replay returns this original historical effect without manufacturing today's slot; load reads current content. Empty semantic projection consumes represented input/residual disposition without new content revision/group (still a bound durable receipt/ack). The owning controller may explicitly CAS-rebase queued changes after acknowledging its own commit; another session's intervening write conflicts.

Discard modes INPUT (clear input and explicitly named pending request) or PREPARATION_ONLY (abandon named pending request while retaining raw). Both CAS generation and pending identity; advance generation, retain terminal intent and prevent delayed resurrection. Missing pending identity cannot implicitly abandon. If commit won first, expected pending disposition conflicts; committed acknowledgement remains replayable. Explicit abandonment of old preparation must not require throwing away recoverable raw. Unsupported future format UNSUPPORTED, persisted contradictions CORRUPT_DATA; malformed client data INVALID_INPUT, stale generation/base STALE_REVISION, existing missing deck NOT_FOUND. Cancellation never implies rollback.

## Deterministic projection and residual rules

Fixed CLDP reason: TEXT_AUTOSAVE `Autosave deck text`; EXPLICIT_CONFIRMED `Edit deck`. Canonical comparison includes reason and exact ordered edits, never an arbitrary caller patch.

TEXT_AUTOSAVE DETAILS checks each field independently against existing committed validity: name nonblank/strict Unicode/UTF8<=1024bytes; description/primer strictUnicode/UTF8<=1MiB. Emit only valid changed fields, in Rename→Description→Primer order. ENTRY validates quantity as positive Int and notes strictUnicode/UTF8<=1MiB independently; produce at most one Replace from exact base entry changing only valid changed quantity/notes. Staged board/finish/labels never leak into this text patch. An invalid field does not block a different eligible field: blankname+newprimer commitsprimer and preservesblankname; quantity `-`+newnotes commitsnotes and preserves `-` plus stagedboard.

TEXT preparation requires at least one valid raw field that differs from canonical base text (including quantity alias `01` versus canonical `1`). Otherwise prepare fails INVALID_INPUT without receipt/promotion; backend explicitly rejects the empty-patch/unchanged-residual fixed point, not just controller suppression. Controller savesraw but does not submit, preventing repeated no-work receipts for invalid-only or staged-only drafts. Alias-only valid quantity may produce an empty canonical patch; consume represented alias without content revision/group. Explicit scope requires every relevant field valid and applies all actual confirmed differences; empty explicit patch may clear an unchanged valid draft without a group.

When current slot exactly equals source, derive residual from the exact submitted body and acknowledged snapshot: reset consumed valid text to result's canonical values, retain every invalid raw field code-unit-for-code-unit and all unconfirmed staged ENTRY choices. Residual exists iff an invalid field or staged difference remains. Base becomes resultrevision only for this exact slot; if no residual, clear to tombstone. All generation transitions checked, including emptycontentcommit. Later raw slot is never normalized/rebased by backend.

EXPLICIT_CONFIRMED DETAILS uses the same ordered actual differences but requires all three fields valid. ENTRY produces one exact base-derived Replace using all confirmed field choices iff any differ. ADD derives one Add from saved selected identity/text/choices and the single entry ID supplied in the frozen patch; validate ID uniqueness and exact identity/content, allocate none during backend prepare/commit/replay. REMOVE derives one Remove for saved target. Other edit kinds, duplicated additions or extra edits fail canonical comparison. ADD/REMOVE always explicit; no text autosave authority.

After acknowledged ADD, only its live owning controller's queued same-selection/form ticket may transform newer input to ENTRY at the one created entry ID; retain newer raw text/staged input. Card/target selection controls stay disabled while prepared; raw text typing remains enabled. A restarted or other-session draft lacking that live ownership correlation is disclosed as a recovery conflict, not automatically inserted/rebased. Consumed current ADD slot clears; subsequent ordinary text edits target the stable created entry.

## Controller and lifecycle

Keep separate latest editable generation, acknowledged raw slot token, and immutable frozen commit request. Serialize raw persistence/promotions while allowing newer typing in memory; older acknowledgement must not erase it or label it saved. Only rebase queued changes across own acknowledged commit, never another edit/undo/restore. Recover stale-base drafts explicitly with conflict disclosure and preserved raw input. Exact uncertain retry retains operation/patch/token and bypasses fresh catalog validation. Existing library/version admission guard must also cover draft commits.

Retained owner schedules monotonic debounce/maxwait, flushes on deliberate navigation, best-effort background, and preserves state on resize. Failure presents not-saved/pending and remain-or-continue choice where appropriate; cancellation is not proof rollback. Drain newest raw input in order; never cancel-and-forget submitted mutation. ADD/REMOVE and other staged/destructive changes remain explicit previews/confirmation.
