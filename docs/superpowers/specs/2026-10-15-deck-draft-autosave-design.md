## Outcome and boundaries

Separately disclose/persist raw invalid editor input, then commit eligible text deltas after at most500ms scheduling debounce, with maximum-wait during continuous input and immediate deliberate-navigation/background flush when possible. This is a scheduling limit, not a guaranteed disk-completion latency. Surface failures; committed content survives reopen; native process-death/lifecycle/device evidence remains distinct. Never claim raw recovery means deck saved.

Each nonempty batch remains one ordinary undo group under LocalDeckEdits. No rewriting/coalescing historical links. Empty semantic deltas create no content revision/group. Autosave only eligible existing DETAILS and ENTRY text. ADD and REMOVE remain explicitly confirmed, never inferred from form validity/default quantity1. New/duplicate-name forms remain explicit workflows, outside this boundary. Recover raw ADD text without trusting stale selected-card proof; after an acknowledged ADD transition to stable created entry, never allocate a second entry on later text changes.

## Complete segregated capability

Root will settle exact Kotlin symbols in NEW core/model/LocalDeckDraftsContracts.kt, using existing models, Outcome/CancelToken and immutable Snapshot containers. Proposed LocalDeckDrafts: load(deckId), write(deckId,expectedGeneration,draft), commit(deckId,token,scope,patch,operationId), discard(deckId,expectedGeneration). Every operation suspend/cancellable, bounded. Load returns persistent generation plus optional draft; token binds generation, immutable base deck revision and canonical payload SHA. One persistent slot per existing qualified deck; concurrent controllers load/reconcile occupancy, not overwrite silently. Raw-generation and deck-revision CAS are independent.

Write preserves exact raw input including invalid text without changing deck head/epoch. Repeated raw write/discard may recognize an exact immediate repetition, but after supersession must conflict rather than overwrite/history-fake. Discard/consume retain a monotonically increasing tombstone generation, including after recreation; overflow fails atomically. Delayed writes cannot resurrect discarded input. No clock/IDs for raw saves. Missing deck NOT_FOUND vs existing empty/tombstone slot; malformed stored metadata/payload CORRUPT_DATA, future format UNSUPPORTED; bad client token/input INVALID_INPUT or stale CAS STALE_REVISION as appropriate. Errors/cancellation never silently truncate or replace last durable input.

Draft body represents actual form: DETAILS name/description/primer; ENTRY target entry ID, raw quantity/notes plus staged board/Knowledge finish/ordered labels; ADD raw quantity/notes/staged choices and optional selected qualified identity/provenance; REMOVE has no text autopromotion. Base is same-deck immutable revision reference, not duplicate full snapshot. ADD recovered proof requires fresh existing currentDeckCard/catalog selection eligibility before new submission; proof failure retains input, never blocks exact committed replay.

Commit scopes TEXT_AUTOSAVE vs EXPLICIT_CONFIRMED. Backend validates token and independently derives allowed patch from exact saved raw/base/scope, compares canonical CLDP with submitted patch. TEXT_AUTOSAVE admits actual changed DETAILS fields or ENTRY quantity/notes only; source entry supplies every unrelated field. Explicit ENTRY may include staged board/finish/labels; explicit ADD uses one frozen entry ID; explicit REMOVE remains an existing confirmed action. Exact DTO/ADD identity framing and residual-slot return shape must receive contract review before code, not be guessed by workers.

Text commit consumes only represented inputs. If staged changes remain, atomically write residual draft generation based on acknowledged result; do not lose board/finish/labels. Result needs historical snapshot plus exact resulting slot disposition/token so consumer can distinguish commit acknowledgement from current state. Empty projection consumes represented raw aliases without content revision/group. Backend must never silently replace the base of input belonging to another session or later generation.

## Controller and lifecycle

Keep separate latest editable generation, acknowledged raw slot token, and immutable frozen commit request. Serialize raw persistence/promotions while allowing newer typing in memory; older acknowledgement must not erase it or label it saved. Only rebase queued changes across own acknowledged commit, never another edit/undo/restore. Recover stale-base drafts explicitly with conflict disclosure and preserved raw input. Exact uncertain retry retains operation/patch/token and bypasses fresh catalog validation. Existing library/version admission guard must also cover draft commits.

Retained owner schedules monotonic debounce/maxwait, flushes on deliberate navigation, best-effort background, and preserves state on resize. Failure presents not-saved/pending and remain-or-continue choice where appropriate; cancellation is not proof rollback. Drain newest raw input in order; never cancel-and-forget submitted mutation. ADD/REMOVE and other staged/destructive changes remain explicit previews/confirmation.
