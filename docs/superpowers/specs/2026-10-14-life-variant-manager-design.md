Authored transition per existing allowedAction ID defines allowed current phases, selection and effects:
- Selection NONE, explicit selected-card multiset with min/max, or deterministic TOP(count) of one declared source zone. TOP requires empty selectedCards (caller must not smuggle an alternative order); explicit selection validates occurrence counts against source zone and bounded1..10000 cardinality. Empty explicit selection may be allowed only if authored minimum0. No selected-card entropy or random permutation overload.
- Source/destination IDs must exactly agree with existing VariantActionDefinition.fromZone/toZone, no invented zones. A move removes exactly selected occurrences preserving unselected order, inserts at explicit TOP/BOTTOM preserving selected order. Same-zone movement is allowed only as authored reorder; capacity checked on final state. If no move, source/destination null and selection NONE; effects may phase/property/reset/count only.
- drawn/discarded are declared append-only histories for this manager policy, not additional physical zones. Each transition explicitly leaves or appends selected occurrences to each history. A deterministic reset restores authored initial state/histories/order/properties (not fresh shuffle), and may not also perform a selection/move. No global history/zone conservation inferred from generic graph validator.
- Optional explicit nextPhase must belong to declared phases; optional literal typed property replacements replace only declared existing keys and never policy marker. Do not invent an expression language or automatic gameplay-condition proof. Additional arithmetic/role/source-specific semantics require separately reviewed authored manager extension.
