## Complete capability and authority

LocalInventory has snapshot(cancel):Outcome<InventorySnapshot>, apply(patch,expected,operationId,cancel):Outcome<InventoryApplyResult>, undo(expected,operationId,cancel):Outcome<InventoryCommit>. InventoryCommit contains InventoryProjection and modifiedAt. Complete sealed InventoryApplyResult has Committed(commit) and Rejected(issues:SnapshotList<DomainIssue>,actualRevision:Revision). Rejected preserves canonical row issues, including LOT_ALREADY_EXISTS for inactive IDs, grants no commit authority and performs no Clock call/write/receipt; it is not replayable. Nonempty issues cannot occur in Committed. Undo still returns InventoryCommit directly. Snapshot includes all active lots, including quantity zero, from one database transaction; capturedAt means last stored inventory modification time, not a fresh Clock reading. Virtual initial state is revision0/time0/empty content. Pure projection is the preview. Apply recomputes from actual complete stored inventory inside the write transaction; caller projections never grant write authority. Existing CollectionRepository remains unbound rather than gaining a partial adapter. Catalog-proven finish eligibility remains a required workflow gate before B10 acceptance; this structural storage capability cannot claim it.

Empty apply records a receipt but no revision advance, Clock call or undo group. Every Committed nonempty apply advances global revision once and creates one logical group, even a semantic no-op. Undo advances revision once and restores exact prior content with newly touched lot revisions; it consumes a group, never toggles or creates another group. No available group returns NOT_FOUND without a receipt. Revision/sequence exhaustion returns PERSISTENCE. Static typed failures, immutable outputs, cancellation before work and between bounded chunks. An admissible nonempty apply/undo reads the injected utcNow exactly once after validation/CAS/integrity and before writes; clock exception returns INTERNAL, CancellationException propagates. Compare epochSeconds then nanos without subtraction; time older than stored time returns INTERNAL with static message and no writes (equal time allowed). Empty/replay/snapshot never read Clock. Unknown acknowledgement after commit is retried with the identical operation ID and input.

## Five additive tables and ordering

All keys are local inventory keys, no source/profile lifecycle cascade. Permanent history has no delete/prune capability.

- inventory_state: singleton, global revision, modifiedAt, latest receipt sequence, current logical group, canonical active-content SHA.
- inventory_lot: permanent lot ID, active flag, last-touch revision, complete CLOL payload with length/version/SHA, quantity projection, last-writing receipt. Avoid speculative unused query projections.
- inventory_operation: AUTOINCREMENT sequence, unique operation ID, method, request version/SHA, expected/result revision, result time/content SHA, change/merge counts and digest, bounded immutable result/reservation descriptor, base group and optional undo target.
- inventory_group: nonempty APPLY receipt sequence as key, previous group, before/after active-content SHA.
- inventory_change: operation sequence plus lot ID; physical before/after images, each with presence, active flag, complete nullable payload metadata and SHA.

FKs: changes→operation; group→own operation and previous group; lot→last-writing operation; state→latest operation/current group; operation base/undo target→already existing groups. APPLY never references its newly created group in its receipt. Its base group is the old pointer; nonempty APPLY result pointer is its own sequence, empty APPLY retains base. UNDO target/base is the old current group, resulting pointer its predecessor. Order inside one IMMEDIATE transaction: operation→changes→new APPLY group→current lots/reservations→state. No deferred FK or provisional receipt may escape an atomic commit. Undo creates no group.

Missing state is virtual initial only if all other four tables are empty. Otherwise CORRUPT; never reset. First successful operation atomically creates state. A first empty APPLY legitimately creates state revision0/time0 with receipt1. Every new successful operation advances latest receipt; replay does not. Verify latest=max(sequence), and revision/time/content SHA agree with latest receipt. Also bind state.current_group to the result pointer derived from the latest immutable receipt: nonempty APPLY→its own sequence, empty APPLY→base group, UNDO→target predecessor. Bind each selected group.previous to its own APPLY receipt base group, and require UNDO base=target plus exact resulting predecessor. Content equality never substitutes for pointer identity: identical Replace/no-op groups have equal hashes but distinct undo history.

## Permanent identities and physical history

Physical absent means null payload. Present inactive and present active both retain a complete nonnull CLOL payload with revision equal last-touch revision. Public projection exposes only active rows; inactive is null, and quantity0 is still active.

Every committed Add ID is permanently reserved, including absorbed merge IDs. Absorbed Add produces an inactive row retaining supplied complete content retouched to the new revision. Remove retains removed complete content as inactive at the new revision. Any Add of an existing active OR inactive ID fails; ordinary edits never resurrect inactive IDs. Undo may restore its exact active before-image, at a new revision. Undo of a newly introduced active lot leaves a permanent inactive row rather than deleting it. Absorbed Add reservations remain inactive UNCHANGED on undo; do not rewrite their revision or release identity. Reservation-only null→null public changes are omitted. Immutable receipt descriptor/digest binds reservation IDs and payloads; active-content SHA alone does not cover inactive state.

## Replay and integrity

APPLY and UNDO share a unique operation-ID namespace. Domain-separated versioned request frame includes fixed local-inventory source, method, expected revision and exact bounded patch, preserving order and reason/evidence strings. Validate and fingerprint immutable bounded input, then look up replay BEFORE current state/CAS/Clock/catalog checks. Same ID with different method/input returns INVALID_INPUT. Historical replay returns stored bounded public delta/time, not a reconstructed whole historical snapshot. Validate receipt method, expected/result arithmetic, images, descriptor counts/SHA and payload SHA before accepting replay.

Canonical active-content SHA streams unsigned-UTF8-ID-sorted complete OwnedLot fields, including zero quantities, identity Knowledge/reasons/evidence; excludes ONLY lot revision and snapshot time. It is a versioned private consistency digest, not authenticity. Bounded cancellation-aware streaming, no giant inventory serialization. On EVERY complete snapshot and before mutation, verify active content against state/latest receipt; current group after digest (or empty anchor for null); selected group before digest equals predecessor after digest (or empty anchor). Applying selected exact before-images must reproduce declared before digest. Touched current content must match selected after-images ignoring only lot revision. Validate selected/immediate predecessor kind, ordering, revisions, metadata and payload; no recursive full-history scan. New APPLY after undo links the remaining pointer, preserving old immutable branches.

## Bounded real database reads and writes

SqlRequest.MAX_ROWS remains101. Complete active inventory uses internal BINARY keyset batches at most100 within ONE DbTransaction, never concatenated mutable public pages. Check count and summed metadata first, then read bounded blobs in that same transaction. At most100000 active lots; total active encoded bytes64MiB; each CLOL at most8MiB. Each operation retains at most16MiB total across BOTH historical images, reservation payloads and result/merge descriptors. Descriptor at most4MiB. Overflow-safe Long sums before allocation/write; reject explicitly rather than truncate. These are rejection thresholds, not measured heap/performance guarantees. Indexed incoming Add-ID queries use actual maxBoundParameters and bounded chunks, not scans of all inactive history. No implicit lifetime inventory cap/pruning.

For current loads AND historical replay/undo, validate SQLite types and bounded scalar text, declared/actual length, version, counts and aggregate budgets BEFORE fetching receipt descriptors or any before/after/reservation payload blobs. Then verify SHA and decoded ID/revision/quantity against projections before trusting bytes. Receipt descriptor and both physical-image sides count toward the same per-operation budget, not independent allowances. Execute reducer under transaction; row issues return InventoryApplyResult.Rejected and reject the whole commit without receipt. Permanent inactive-ID conflicts add canonical LOT_ALREADY_EXISTS before accepting a projection. Receipt/group/change/lot/state writes, cancellation and injected failures must roll back together. Snapshot/read transactions must not mutate state or call Clock. CancellationException propagates through DbTransaction, never converted to domain failure. Check cancellation before/after codec calls, between keyset batches, SQL writes and bounded digest/request chunks, and at the final DB callback boundary. Existing CLOL calls are bounded but non-cancellable internally; no <=1024-unit interruption claim applies inside that codec.
