## Outcome and complete capability

Enumerate immutable named checkpoints, preview a complete historical diff, restore without content loss, and keep an enumerable pre-restore recovery checkpoint. Existing deck_revision history is not this feature. Reuse DeckVersion and DeckDocumentDiff, not the unimplemented aggregate DeckRepository.

Proposed LocalDeckVersions methods (all suspend, final CancelToken, Outcome):

- capture(id:DeckId, expected:Revision, label:String, operationId:EntityId):DeckVersion
- list(id:DeckId, page:PageRequest):Page<DeckVersionSummary>
- load(id:DeckId, versionId:EntityId):DeckVersion
- previewRestore(id:DeckId, versionId:EntityId, expected:Revision):DeckRestorePreview
- restore(id:DeckId, versionId:EntityId, expected:Revision, recoveryLabel:String, operationId:EntityId):DeckRestoreResult

DeckVersionSummary contains existing DeckVersion metadata except manifest, plus kind USER/RECOVERY and nullable restoredTargetVersionId. DeckRestorePreview contains actual current DeckSnapshot, selected DeckVersion and complete DeckDifference, oriented current to historical target. Historical revision/modifiedAt are labeled historical metadata, never predicted committed fields. It predicts neither future time nor write authority. DeckRestoreResult contains committed DeckSnapshot and exact recovery DeckVersion. Restore independently rereads all inputs transactionally. Existing DTO/wire types are not silently changed.

On load/preview/restore, validate historical source.createdAt against the immutable revision0 anchor; reject contradiction instead of concealing it by replacing createdAt. USER requires CAPTURE, target NULL, sourceRevision=receipt.resultRevision. RECOVERY requires RESTORE, sourceRevision=receipt.resultRevision-1 (checked), an existing earlier target, and exact immutable restored-result content matching that target except the explicitly replaced revision/modifiedAt. Recompute creating CLDR request fingerprint from stored exact metadata and compare its receipt SHA. These bindings also apply to list metadata and replay, with payload comparison only when payloads are loaded. The initial full-storage HOLD was released only after all repaired r2 invariants received independent review (disposition below). Implementation/runtime acceptance remains separate.

Labels exact/nonblank strict UTF-8 <=1024bytes; duplicate labels allowed. Local provider/deck IDs and operation/version IDs use existing identifier bounds. List of absent deck is NOT_FOUND; existing deck with no checkpoints returns an empty page. Stored metadata_version newer than1 is UNSUPPORTED, malformed/nonpositive version CORRUPT_DATA. Wrong deck/version pair is NOT_FOUND, malformed input INVALID_INPUT; mismatched expected STALE_REVISION; contradictory retained storage CORRUPT_DATA; known unsupported wire remains UNSUPPORTED. CancellationException propagates; unknown acknowledgement may have committed. No zero/missing substitution, no implicit downloads or catalog authority.

## Reviewed compatibility framing — root-selected revision 2

Big endian. F(s)=u32 byte length followed by exact nonblank strict UTF8 <=1024bytes. N(s)=u8(0) for absent, u8(1)+F(s) for present. Explicit enum tags, never ordinals.

- CAPTURE: ASCII CLDR + u16(1) + u8(4) + F(provider)+F(deck)+i64(expected)+F(label).
- RESTORE: same common prefix with tag5, then F(targetVersionId)+F(recoveryLabel).
- Scope: SHA256(ASCII CLVD+u16(1)+F(provider)+F(deck)), raw32bytes.
- Cursor: ASCII CLVC+u16(1)+i64(globalReceiptEpoch)+i64(lastCreationSequence)+scope32; exactly54bytes, canonical unpadded base64url72chars. Reject invalid framing/ranges/scope/anchor as INVALID_INPUT; valid cursor with changed epoch is STALE_REVISION; malformed persisted anchor metadata/receipt is CORRUPT_DATA. Validate epoch before anchor, scope before query; sequence>0 and <=epoch. SnapshotReference uses the captured receipt epoch, not content revision.
- Named metadata: ASCII CLNV+u16(1)+F(versionId)+F(provider)+F(deck)+F(label)+i64(createdSeconds)+i32(createdNanos)+i64(sourceRevision)+N(predecessorVersionId)+u8(kind USER0/RECOVERY1)+N(restoredTargetVersionId)+i64(creatingSequence). SHA256 lowercasehex64 in storage. Canonical field checks before digest; metadata hash supplements (never replaces) recomputed CLDR receipt/request/result relationship.
