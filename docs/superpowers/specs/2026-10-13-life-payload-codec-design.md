# Private life payload codec design

2026-10-13. **Architecture APPROVE after independent Astra review; no implementation or runtime evidence.** This is a private persistence format for `PlayerProfileSnapshot`, `GameSnapshot`, and `GameEventArchive`, using the published core model as the type authority. It adds no public model, service, schema, UI, exchange format, or dependency. Root owns the later integration and may revise this draft after source review.

## Boundary and format

Use a small, deterministic, bounded binary codec built from `DataInputStream`/`DataOutputStream`, explicit UTF-8, and primitive writers. Do not use Java serialization, reflection, class names, `enum.ordinal`, JSON defaults, or `DataOutput.writeUTF` (modified UTF-8). The proposed private API has three typed `encode`/`decode` pairs, one per root type. It never accepts a caller-supplied generic class discriminator. The repository maps malformed payloads to visible `CORRUPT_DATA`, and a newer unsupported version to a visible unsupported/version failure; neither case deletes, repairs, overwrites, or silently defaults a row. Encoding invalid models fails before persistence.

Envelope v1 is big-endian: four fixed ASCII magic bytes `CLLP`, unsigned byte kind (`1` profile, `2` snapshot, `3` archive), unsigned short wire version (`1`), signed int payload-byte count, then exactly that many payload bytes. No checksum is proposed: the storage transaction/integrity layer is separate, and a checksum would not certify lineage. Decoder checks the complete input length against the kind's cap before allocating or decoding, validates magic/kind/version/declared length, rejects an incorrect root kind, and requires exact end of frame and payload. It rejects all unknown tags and newer versions. Future v2 must have its own decoder and deliberate migration; v1 field order and tag values are immutable. The `GameSnapshot.version` and `GameEventArchive.version` fields are **domain values**, serialized independently of wire version and restored exactly; a domain version unsupported by its future consumer must be rejected at that consumer boundary, not mistaken for the wire version.

The limits are encoded-byte limits, including envelope: profile and snapshot at most **4 MiB**, one archive at most **16 MiB**, one UTF-8 string at most **64 KiB**, counter definitions at most **128** independently per profile/settings (both embedded snapshots may each retain128; do not impose an erroneous128 aggregate across their before/after copies), one flat `GameAction.Group` at most **1,024** actions, and repository page size **1–100** (page enforcement belongs to the repository). A profile uses the snapshot-sized cap as a conservative policy, not a new product guarantee. The archive's two embedded snapshots each independently obey 4 MiB, with the whole archive obeying 16 MiB. Never truncate event history, random faces, evidence, variant definitions, or any field to satisfy a cap. Encoding reports a visible size failure; decoding reports corrupt data. Before every list allocation, validate a nonnegative count against the field's semantic bound, remaining bytes/minimum element width, and a per-root cumulative decoded-element budget derived from the byte cap; then append incrementally to bounded collections and freeze with `SnapshotList.copyOf`. The top-level byte cap remains the final defense against many individually small lists. `RecordedRandomValue.Dice.faces` retains its model limit of 10,000. Variant action/zone/card/phase/property and evidence lists use explicit counts bounded by remaining bytes/minimum encoded element width and the cumulative budget. Do not invent a1,024 variant/evidence-list ceiling:1,024 is the approved flat-action-group limit. Specify count checks per element type before implementation; encoded byte caps remain engineering limits with visible failure, never truncation.

## Primitive rules

Optional values use a single byte `0`/`1`; booleans also use only `0`/`1`. Strings are signed 32-bit byte length followed by strict UTF-8 with malformed/unmappable input rejected and no normalization; verify the byte limit before allocation. Write exact identifier components, never `toString()`: `GameId`, `DeckId`, `CardId`, `OracleId`, `FormatId` are `(ProviderId.value, raw)`; `ProviderIdentity` is `(provider.value, kind, rawId)`; `EntityId`, `GenerationId`, `LanguageTag`, `ResourceUri` are their exact values. Reconstruct their value types to apply model validity checks. `ContentHash` writes `(algorithm, hex)` exactly. `Revision` and event IDs use signed 64-bit values with model range checks; `UtcTimestamp` writes signed 64-bit epoch seconds plus 32-bit nano adjustment `0..999999999`, supporting negative epoch and extreme representable seconds without milliseconds conversion.

Finite `Duration` writes its exact `toComponents` pair: signed64-bit whole seconds truncated toward zero and signed32-bit nanoseconds in-999999999..999999999, with matching signs when seconds are nonzero. Using floor seconds can make the intermediate seconds conversion infinite at the finite negative boundary, so it is deliberately avoided. Decode by checked reconstruction and re-encode to the same pair to reject aliases, mixed-sign noncanonical pairs, overflow, rounding, or infinity; do not use `inWholeMilliseconds`, which loses sub-millisecond values and negative overtime. Encode performs the same exact round-trip test before writing. Signed clock anchors and finite overtime survive. `ArtCrop` stores four raw IEEE-754 64-bit bit patterns; reconstruct and apply its finite/range/positive-area constraints. Preserve representable `-0.0` exactly rather than silently normalizing it. Other numeric fields use their declared signed widths and constructors; no parsing through floating point. `Knowledge<T>` has fixed tags `1 Known`, `2 Absent`, `3 Unknown`; the latter retains reason and every `Evidence(description,source?,recordedAt?)`. Generic `Known` uses the writer for its statically known field type, so it cannot be reinterpreted as another type. Source/provenance strings and URIs are data, not authorization.

Every enum and sealed branch has an explicit wire tag table; never infer order from Kotlin declaration. V1 assigns these branch tags: `CounterLossPolicy` None/AtOrAbove/AtOrBelow = `1/2/3`; `GameArtReference` Local/CachedCard = `1/2`; `SeatParticipation` Active/Eliminated = `1/2`; `GameAlertTarget` SeatClock/SharedCountdown/TurnTimer/GameTimer = `1/2/3/4`; `VariantValue` Text/Integer/Flag/Card = `1/2/3/4`; `RandomRequest` Dice/ContinueDice/Coin/SeatPick/SeatOrder = `1/2/3/4/5`; `RecordedRandomValue` Dice/Coin/SeatPick/SeatOrder = `1/2/3/4`. `GameAction` tags `1..29` in the **explicit sequence** SetCounter, SetAdjustmentStep, SetCommanderLifeDeduction, UpdateCounterDefinition, AddCounterDefinition, EliminateSeat, RestoreSeat, SetMonarch, SetInitiative, SetDayNight, SetBlessing, SetSeatAppearance, SetGamePresentation, FinishWithOutcomes, DismissLossCandidate, PassClock, SetElapsedPaused, AcknowledgeGameAlert, SetAlertPreferences, RequestRandom, AdjustCounter, SetCounterHidden, RenameSeat, ReorderSeats, SwitchTurn, ClockPause, Variant, Finish, Reopen; tag `30` is Group. Freeze this table in a golden fixture before implementation. A new enum or sealed case must fail exhaustive codec compilation and receive a new tag/version decision. Unknown cases never map to OTHER/UNSET.

The enum tags are likewise fixed per named type, starting at `1`: `GameStatus` ACTIVE, PAUSED, COMPLETED; `CounterRole` LIFE, COMMANDER_DAMAGE, COMMANDER_TAX, OTHER; `CounterResetPolicy` MANUAL, ON_TURN_START; `CounterPreset` POISON, ENERGY, EXPERIENCE, RAD, STORM, MANA, TREASURE, CHARGE, BLOOD, FOOD, CLUE, RING, PLANESWALKER, SAGA, SIEGE; `SeatOrientation` UPRIGHT, CLOCKWISE, INVERTED, COUNTERCLOCKWISE; `GameLayoutMode` TABLETOP, OPERATOR; `ArtFit` CONTAIN, COVER; `SeatExitKind` CONFIRMED_LOSS, CONCEDED, DISCONNECTED, MANUAL; `DayNightState` UNSET, DAY, NIGHT; `SeatResultKind` WIN, LOSS, DRAW; `SeatClockMode` NONE, CHESS, PER_TURN, SHARED; `ClockZeroPolicy` ALERT, PAUSE, ELIMINATE; `ClockUndoPolicy` RESTORE_TIME, KEEP_ELAPSED; `VariantNamespace` PLANECHASE, ARCHENEMY, BOUNTY, CUSTOM. Each mapping is a named constant/`when` arm, pinned by fixture; Kotlin source order is not the wire rule.

## Complete v1 object graphs

The profile payload writes `PlayerProfileSnapshot(id,revision,value)`; value writes `name,preferredLife,counterDefinitions,appearance,commanders,adjustmentStep`. Each counter definition retains ID, label, min/max, initial, loss policy, custom, role, color, preset, reset policy. `SeatAppearance` retains color, art, fit, crop, orientation; local art retains relative path and checksum; cached art retains full `CardIdentity` and asset ID. `CardIdentity` retains oracle/printing `Knowledge`, raw provider identity, original-name `Knowledge`, and language. Commander slots retain ID, card identity, label. No profile defaults may be filled during decode.

The snapshot payload writes fields in declared v1 order: `id,version,revision,settings,status,startedAt,endedAt,seats,counters,activeSeatId,turnNumber,clock,variants,lastEventId,result,designations,elapsed,alerts`. `GameSettings` includes format `Knowledge<FormatId>`, initial life, every counter/variant definition, clock mode, random seed, presentation, adjustment step, commander-life deduction, elapsed-timer settings and all alert preferences. Each seat includes identity/name/profile ID, exact deck `Knowledge<DeckReference>` (including deck revision/name/tombstone), order, commanders, appearance and participation with elimination evidence/time. Counters retain definition/seat/commander-slot IDs, value and hidden state. `SeatClockState` retains mode, every `SeatTime(initial,remaining)`, active seat, optional `ClockAnchor(wall,monotonic,processSessionId)`, paused, zero/undo policy, fired alert IDs and optional shared countdown. `GameDesignations` retains monarch, initiative/note, day/night and blessed seats; elapsed state retains both durations, paused, optional anchor and `turnLineageId: Knowledge<EntityId>`. Alerts retain ID/game ID/target/fired/acknowledged timestamps. `GameResult` retains ID/game ID/winners/finishedAt/reason/revision/retracted and seat results with exit kind. `LossEvidence` retains both optional IDs, observed value, policy, rule-version `Knowledge` and rationale.

Variant definitions retain provider identity, namespace, version, instructions, all allowed action definitions (including from/to zones and per-phase maximum), zone definitions, phases, cards, full card image `Knowledge<ResourceUri>` and action IDs, and every card/definition `Provenance` and `SourceNotice`. `Provenance` retains provider/source/version/sourceDate/fetchedAt/effectiveAt/generation/checksum/notice; `SourceNotice` retains provider/title/license/attribution/URI. Variant state retains definition identity/version, zones with ordered card identities, drawn/discarded identities, phase, typed properties, seed, and action counts. The decoder reconstructs exact model constructors but does not infer source authenticity from these bytes.

An archive payload writes `GameEventArchive.version`, then `GameEvent(id,gameId,groupId,action,at,undoOfEventId,revision,randomResults)`, then `GameActionProvenance(eventId,before,afterAction,reading)`. The two provenance snapshots use the snapshot **body** codec with length prefixes and independent 4 MiB checks; they contain no event archive, preventing nested archive recursion. The time observation retains finite monotonic duration, UTC wall time and process-session ID. Every action branch writes every constructor field, including full definitions, appearance, results, loss evidence, random request, variant selection, and `Group.groupId` plus actions. Group depth is exactly one: reject a Group child at encode/decode, and reject more than 1,024 flat children. Random results retain request ID/time and all value fields: dice sides, every face, sum, requested, batch index, remaining; coin side; picked/eligible seat IDs; full ordered seats. No recomputation replaces recorded values. Existing model constructors' local invariants run on decode; additional game-wide lineage/undo/replay checks belong to the future service.

## Ownership, evidence, and limits of the result

Implement later as small private files in the platform-free `feature:life` internal payload package, accessible to its real service implementation through the existing core.model.Database port (no dependency on Android data:storage internals): `LifeWirePrimitives` (frame, counts, strings, time, IDs, Knowledge, fixed tag tables), `LifeProfilePayloadCodec` (profile and shared appearance/counter/card pieces), `LifeSnapshotPayloadCodec` (snapshot/settings/seat/clock/variant graph), `LifeActionArchivePayloadCodec` (actions, event, random records, archive). Keep a single internal tag registry and no public generic serializer. The archive codec may call the snapshot-body codec; the reverse dependency is forbidden. The data:storage module owns schema/entities/migrations and opaque payload columns, not this feature-internal codec. No dependency or module change is part of this design packet.

First pin profile v1 golden byte fixtures and round trips (including exact Knowledge reasons/evidence, local/cached art and counter roles); then snapshot fixtures with absent/unknown evidence, variant provenance, signed/extreme UTC, negative overtime, alerts and turn lineage; then every action/random branch and archive with both complete snapshots. Assert encode→decode model equality and deterministic bytes, plus decoding the pinned v1 bytes after implementation changes. Mutate one byte at every header boundary and representative nested tags; test truncation at each small prefix/field, cross-kind decoding, unknown/newer version, unknown enum/sealed tags, malformed UTF-8, trailing bytes, bad booleans/counts/lengths, oversized strings/roots/lists/group, noncanonical duration pairs and invalid IEEE values. Exact v1 tests should prove no default-field omission. A later v2 decoder needs frozen v1 golden evidence and explicit migration behavior.

Successful decoding proves only structural validity against this private wire version. It does **not** certify persisted event lineage, valid undo provenance, authentic variant definitions, trustworthy source URIs, safe local-art paths, or image privacy/ownership. Those checks stay with service/repository/art gates before acting on decoded data. This spec proposes no schema write, service registration, retention change or product behavior. Next delta after Astra approves: pin profile goldens and the v1 tag registry in a test-only packet, then implement the four private codec units in dependency order with real persistence integration reviewed separately.

Root review refinements: keep codecs internal to the pure-JVM life module so the future service can actually call them without importing another module's internal API; use signed truncation Duration components for full finite-boundary fidelity;128 counter definitions applies independently to each settings graph, not to both archival copies combined; generic list bounds derive from encoded element widths/byte budgets, not an invented variant/evidence cap. A future stored-row reader must check `length(payload)` in its read transaction before asking the database adapter to materialize a BLOB larger than the applicable cap. This preflight and actual resource behavior remain service/persistence gates.

Independent review outcome: APPROVE bounded implementation. Before primitive/sourcefreeze: outputcapacity checked beforegrowth, strictUTF16-toUTF8 with no replacement, concreteper-list minimumwidth/cumulativebudget, embedded snapshot body plus hypothetical11byte envelope <=4MiB, typed malformed/oversize versus unsupported-wire errors; never catchfatal JVMerrors/cancellation ascorruptdata.
