# Checked life profile persistence

Implement the existing PlayerProfileRepository through core Database, Clock and IdSource in pure-JVM feature/life. A twelve-method LifePayloadCodecPort in core/model is implemented by the actual storage codec; no production feature-to-storage edge. Actual SQLite/codec integration tests live in storage with a documented test-only dependency on feature/life. No schema/version change or DI/GameService binding.

Creates allocate strict UTF8 nonblank IDs<=256bytes; invalid generator output is INTERNAL, collisions typed PERSISTENCE, never overwrite. Draft serialization keeps codec4MiB limits without truncation. Store original name and NFC then Locale.ROOT lowercase projection, revision0 and exact Clock timestamp. Read/update/delete validate persisted IDs, revision, timestamp pair, blob length and decoded draft/name/fold agreement. Missing rows are NOT_FOUND; stale revisions STALE_REVISION; corrupt storage CORRUPT_DATA. Guard Long.MAX_VALUE before increment. Exact affectedRows1 is required. All SQL parameters are bound.

Every operation runs in Database.transaction. Typed codec/validation/query failures propagate without Success(Failure); cancellation escapes and rolls back. No swallowed query failures. Update/delete check expected revision and CAS inside transaction; deletion touches only life_profile and preserves frozen game history/art references.

List orders by profile_id COLLATE BINARY, uses a strict canonical version1 URL-base64 UTF8 last-ID cursor. Public limits1..100. Fetch at mostlimit+1 metadata rows (no blobs), each ID<=256bytes/payload<=4MiB; choose at most8MiB encoded bytes, fetch selected blobs one at a time in the same transaction, validate exact length/projections. Return at least one row when present; cursor is last returned ID whenever lookahead/budget leaves more. SnapshotReference identifies local profiles without promising cross-page snapshot isolation. Changes between pages may affect membership, never silently alter a cursor.

Independent design review approved these boundaries in the current recovery session. Existing user instructions delegate routine implementation and continuous local execution. Tests cover actual bundled SQLite CRUD/reopen, stale/max revision, corruption, bytebudget/keyset pagination, malformed cursors, generated IDs/collisions, cancellation rollback and frozen history preservation. Room/Android adapter evidence remains distinct from the host test adapter.

Stored variable text is projected as length-bounded BLOB bytes and strictly decoded in the repository; driver replacement of malformed SQL TEXT must not turn corruption into a valid Unicode name/ID. Integer metadata is type-guarded before retrieval. This was pinned by an actual SQLite invalid-UTF8 reproduction.
