# Checked game creation/read persistence foundation

Root task cx-m2-life-game-store-01, Android v1 local-first execution. This concrete foundation is not GameService, action/history persistence, full game graph/source/undo lineage validation or UI acceptance. Root retains model/schema/DI and feature/life ownership.

## Boundary

Public concrete feature/life `SqlLifeGameStore(Database, LifePayloadCodecPort)` exposes `create(input: GameCreation, initialize: () -> Outcome<GameCheckpoint>, cancel: CancelToken): Outcome<StoredLifeGame>` and `read(id: GameId, cancel: CancelToken): Outcome<StoredLifeGame>`. `StoredLifeGame` carries immutable original `creation`, current `checkpoint` and nonnegative `sequence`. Public visibility permits real codec/SQLite integration tests in storage without a production reverse dependency; this is not a new core service port or DI binding.

Use a lazy initializer instead of embedding an incomplete game/variant engine in the store or constructing setup before operation lookup. The initializer owns fresh identity/time and authentic engine initialization; the store owns transaction/idempotency/checked persistence. It is synchronous/local: no nested database transaction, network, UI or external durable effects. A matching committed retry never initializes. Initialization may run again after cancellation/crash/rollback; promise uniqueness of committed setup, not exactly-once callback execution.

## Creation and retry

Within one Database.transaction: validate operation identity (strict UTF8 codec string limit65536bytes), look up globally unique operation ID, validate the existing stored record, compare decoded original GameCreation with input, return its CURRENT checkpoint/sequence if equal. A conflicting operation input is INVALID_INPUT, never overwrite or create another game. Read/retry must not require current settings/seats to equal original creation after legitimate edits. Compare semantic input across codec versions; a hash/header change is not an idempotency verdict.

For a new operation, encode original creation (current codec2/root6,<=4MiB), then invoke initializer and propagate all typed statuses unchanged. Check initial snapshot: supported model version1, revision0, positive source/raw game identities within strict codec UTF8 limits, exact input settings/seats/clock; noncompleted ACTIVE or PAUSED status with all countdown and elapsed timers paused, elapsed0, no anchor, turn0/no active seat, default designations, genuine Knowledge.Absent ended/result/event/settled/turn lineage (preserve reasons; reject initial Unknown/Known), no alerts/recovered session. Counter states may be omitted (existing reducers interpret definitions' initial values); any supplied state must have valid distinct seat/definition/commander scope, initial value and hiddenfalse. Variants must not be silently dropped: exactly one state for each definition with no duplicate/extra definition/state IDs, every defined zone present exactly once with no extras, and versions/card references match definitions; authentic initialization/source approval remains the engine's job. An engine that cannot initialize a requested variant returns typed UNSUPPORTED before any rows are written.

Encode checkpoint<=4MiB+65536. Compute SHA256 over exact original creation bytes; hash is an integrity projection. Insert life_game at revision0/sequence0 and updated=start timestamp, then all1..6 seat-search projections with original Unicode spelling and NFC+Locale.ROOT lowercase names; known decks retain source/raw/name, absent/unknown decks project all deck fields NULL while the checkpoint preserves exact Knowledge. No initial event/result/alert rows. Exact affectedRows1 for every insert; collision/failure/cancellation rolls back parent and every seat. Initializer IDs are preserved, never regenerated/truncated by store.

## Read checks and limits

All reads are transactional and metadata-first. SQL CASE/type/byte-length guards bound source/raw/operation/status/hash and seat/deck texts before driver retrieval; project text as BLOB and strictly decode UTF8, never trust replacement characters. String limit65536bytes (folded text262144bytes); hash exact64 lowercase hex; status enum; integer revision/sequence>=0; timestamps typed with nanos0..999999999 and nullable ended pairs bothnull or bothvalid. Validate creation length1..4MiB and checkpoint1..4MiB+65536 before fetching each blob separately. Recompute creation hash and require decoded creation.operationId equals row.

Require checkpoint snapshot source/raw ID, revision, status, start and Known-ended projection equal row, and validate complete1..6 seat-search roster against the CURRENT checkpoint: stable seat identity, original/folded player name and exact optional deck identity/name pairs. Eliminated seats remain in roster; profile deletion never rewrites it. Updated timestamp must be valid, not assumed equal latest clock anchor. Do not compare current settings with immutable original creation. Unsupported snapshot model version returns UNSUPPORTED; inconsistent projections/payloads are CORRUPT_DATA; absent game NOT_FOUND. Decode stored invalid data as CORRUPT_DATA, invalid initializer/new input as INVALID_INPUT.

This packet checks creation and core/seat projections. Subsequent event/checkpoint mutation adapter and full service MUST validate authoritative domain graph, result/alert projections, event/undo/settled lineage, clock session recovery and source authority before operational binding. read() is not a certificate for those unimplemented boundaries. No write/CAS/action/history APIs or silent repair in this packet.
