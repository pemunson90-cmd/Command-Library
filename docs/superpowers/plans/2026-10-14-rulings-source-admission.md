## Durable receipt

Actual admission pins a current completed fixed-endpoint metadata job, validates its exact canonical plan/artifact/consent and bounded source URI/representation, reads contiguous verified chunks and compares actual raw bytes/hash before invoking the strict metadata decoder. Only that path may issue a receipt. A public candidate, caller JSON, URL pattern or arbitrary VerifiedArtifact cannot issue one. Metadata URI in the body is distinct from the fixed requested discovery endpoint; both remain retained.

Add one additive schema8 `catalog_source_receipt` table: receipt_id TEXT PK, metadata_job_id TEXT unique/indexed, payload_schema_version INTEGER and receipt_payload TEXT. No FK to jobs/artifacts: deleting their retention must not erase source authority required by already-persisted file plans. Full bounded receipt retains original literal metadata body, exact metadata plan/artifact/consent, issue time and source-policy version; derived candidate is recomputed and validated on rehydration. Use a bounded versioned strict codec, exact numeric fields/Unicode and full projection consistency, with SQL byte-length guard before reading payload. Existing27schema7 entities stay identical; migrations/history/goldens are preserved.

Receipt issuance is idempotent per exact metadata job/artifact. Validate a preexisting receipt before returning it, never overwrite a conflicting proof. Pin remains alive through durable insert/acknowledgement; ambiguous commit is reconciled exactly or left unknown, never fabricated. Atomic policy budget controls receipt count; no silent truncation of queued-job authority. Profile rehydration uses small identity pages, one bounded payload at a time, then retains only bounded canonical candidate facts needed by the engine's synchronous profile/wire validator. Exact cache/count budgets and failure semantics must be explicit before implementation; malformed authority fails closed with typed error. Do not materialize a page of large receipt bodies or rerun global acquisition recovery on each receipt issue/read.

Proposed initial budgets:4096receipts, at most8KiB UTF8 of canonical candidate facts per receipt, and at most2MiB+128KiB per serialized receipt (metadata body itself remains1MiB). Stream small identity pages and materialize one receipt body at a time. This bounds retained candidate text to32MiB plus bounded object overhead; never retain all original bodies in the synchronous validator. Capacity exhaustion rejects only new issuance with an explicit typed source-unavailable result; it does not delete or hide existing receipts/jobs. Rehydration of an out-of-budget or corrupt store fails closed, without silently dropping old queued-job authority. No automatic receipt purge is introduced in this unit.

Also cap total retained serialized receipt bytes at64MiB, enforced atomically alongside count during new issuance. Rehydration checks that aggregate budget before loading bodies, bounding disk/parser work rather than allowing4096maximum-sized receipts. Existing idempotent receipts remain readable at capacity; no data is truncated. Loading/publication and new issuance are serialized by the sole factory's admission owner; there is no second live recovering factory over the same jobs. These are unmeasured safety ceilings, not a Fold7 performance claim.
