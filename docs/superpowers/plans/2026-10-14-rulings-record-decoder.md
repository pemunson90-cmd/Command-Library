# Strict ruling-record decoder

Status: internal decoder implemented; independent design/source review refinements applied; focused32tests pass17s. Parent: orch-kotlin-k3-offline-data-01. No new transfer, public port, schema, dataset activation or UI registration in this unit.

The accepted personal-source review identifies the official rulings feed as gzip JSONL and requires preserving oracle_id, source, published_at and comment. The existing metadata decoder establishes structural candidates only. Existing Ruling uses an instant and has no explicit publisher-source field, so this unit must not force source dates into instants, fabricate provider IDs, or lose source information by adapting prematurely to that old public DTO.

Implement an internal immutable ScryfallRulingRecord and strict single-object decoder in feature/catalog. Preserve the source-qualified Scryfall Oracle UUID, exact supported source string (wotc or scryfall), exact canonical Gregorian YYYY-MM-DD publication date, and untrimmed Unicode comment. Source date is a calendar date, not corpus freshness or a time-zone assertion. Unknown language remains unknown: never label this prose English by inference. Do not synthesize a publisher ruling ID, fetched time, generation, checksum or provenance.

Use the existing strict duplicate/Unicode/depth JSON parser. Bound raw record and retained/unknown string UTF-8 bytes with named internal safety constants, unrelated to advertised corpus size. Require object=ruling and required fields with exact types. Validate canonical lowercase hyphenated UUID, actual proleptic Gregorian dates in years0001–9999 including leap-year rules, supported source, nonblank bounded comment; preserve leading/trailing whitespace of accepted content. Reject unknown source rather than silently presenting it as official. Ignore bounded future fields without trusting a URI or future identity field. Parsing does not authorize network, prove source authenticity, deduplicate a whole feed or activate storage.

Batch meaningful cases before one focused catalog JVM run: exact Unicode/source/date preservation, both publishers, missing/null/wrong types, invalid UUID/date/source, duplicate keys/trailing JSON, escaped invalid Unicode and unknown-field nesting/string/total byte limits. Add framed streaming coverage only if it exercises an integration gap beyond existing JsonLinesFramer tests. No full-suite or emulator repeat for this isolated internal parser; broader persistence/acquisition acceptance comes with their later implementation.

Next units retained: exact source/retrieval authority and per-intent consent for fixed official metadata plus offered artifact; immutable public ruling/source/date representation; additive persisted ruling generations and atomic activation/rollback; local Oracle-linked ruling reads/UI; genuine full-feed and device validation. This internal decoder closes none of those obligations.

Review refinements: validate raw Unicode with strict UTF-8 encoding and the record cap before JSON tree allocation. Bound unknown field names/values as well as retained strings. Existing strict parser rejects duplicate fields/invalid escaped Unicode and enforces depth/node bounds. Reject year0000 explicitly; no platform calendar/timezone/clock is required. Canonical UUID spelling is checked directly.
