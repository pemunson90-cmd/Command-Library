# Indexed typed query projections and resumable preparation

Root architecture proposal under SPEC A07/A08 and D-17/D-28, based on the completed independent review and exact numeric primitivefadad88. Existing original payloads, canonical identities, private acquisition/consent and active pointers remain authoritative. This is a staged implementation design, not evidence that indexed AST execution exists. First implementation packet is additive physical schema/export/migration proof only, after independent review. No unreviewed schema edits yet.

## Selected approach and alternatives

Use versioned derived facts in the existing shared database. Catalog owns extraction/preparation from its retained original rows; search owns typed expression validation/semantics and SQL compilation; storage owns Room schema/migrations. Reject query-time JSON numeric casts because they lose decimal precision and repeatedly parse source payloads. Reject a parallel private search database because it splits durability/ownership. No source payload is rewritten or reclassified as canonical merely to build an index. Existing literal name/Oracle readers remain usable while derived preparation is incomplete.

## Physical schema9 first packet

Add only the following tables and indices, registering actual Room entities/migration8→9 and exporting real KSP9. All28 schema8 entities and retained rows stay unchanged. Derived facts carry generation_id and projection_version; v1 is a projection format, distinct from database/payload/compiler versions. Every abbreviated card/printing fact identity below includes generation_id AND projection_version plus its source-qualified identity/language. All ordinary derived facts have FKs to their build and original source identity with CASCADE, plus explicit indices for child lookups. No derived table owns user/source data. FTS cannot have FKs, so cleanup and readiness validation explicitly cover its rows.

- `catalog_search_build`: PK(generation_id,projection_version), FK catalog_generation. Status PREPARING/READY/FAILED, phase CARD/PRINTING/VERIFY, nullable last provider/id/language key, completed card/face/printing/text/legality counts, optional bounded diagnostic. Original generation/status/source/payload version validated before beginning. No timestamps or source versions invented. Counts/cursor and derived writes always commit together. READY only after complete validation.
- `catalog_search_card_fact`: PK(generation,version,provider,oracle,language), FK exact oracle_card and build. Name is held in text facts. Nullable card-wide mana_value_key/colors_mask/identity_mask/layout/reserved and canonical power/toughness/loyalty/defense keys; oracle_text_known/type_known/keywords_known flags; actual face_count. NULL is unknown comparison evidence; mask0 is known empty. No fake zero/false. Card-wide mana value/identity are never attributed to a face.
- `catalog_search_face_fact`: same identity plus actual nonnegative face_index, FK original card_face and build. Numeric stat keys, nullable face colors from actual retained face JSON, oracle_text_known/type_known. Never synthesize a source face ID or assign card-wide values to a face. Canonical facts stay in the card table rather than a fake face ordinal.
- `catalog_search_printing_fact`: PK(generation,version,provider,printing), FK original printing and build. Exact set/language, nullable rarity/finish_mask/gamechanger and legalities_known flag. Oracle membership comes from the existing direct relation plus printing_oracle_membership, preserving reversible-printing source slots. No printing is attached to a guessed whole-card identity.
- `catalog_search_legality_fact`: PK(printing fact identity,format), FK printing fact. Original source-qualified format and recognized legality status. Missing/malformed values remain unknown; absence of a format row never proves not-legal. Original dictionary/unknown values remain in source payload, not silently replaced.
- `catalog_search_text_fact`: PK(card identity,scope_kind,scope_index,field). Scope CANONICAL uses index0 as a namespace slot, FACE uses actual face_index, KEYWORD uses actual array ordinal. NAME/ORACLE_TEXT/TYPE/KEYWORD and normalized literal value. FK exact original oracle/build; face/keyword namespace validated by materializer/readiness. Separate rows prevent phrase matches from bridging different faces or keyword strings. Known-empty fields may have an empty row; unknown fields have no value row and explicit knownness in parent facts.
- `catalog_search_text_fts`: FTS5 value column, tokenizer `unicode61 remove_diacritics 2` (same pinned behavior as existing catalog FTS), with UNINDEXED generation/version/provider/oracle/language/scope_kind/scope_index/field. Mirror one row per text fact; fixed tokenizer policy/version documented and tested against scalar normalization. No source-provided SQL/regex/FTS expression is executed.

Indices: deterministic card-name order stays in oracle_card; derived scalar indices begin generation/version and the compared field, ending source identity; face/printing/legality lookup indices cover the correlated source identity. Text exact lookup includes generation/version/field/normalized value. Numeric key columns use TEXT/BINARY (no numeric affinity). Color bits W1/U2/B4/R8/G16, finish NONFOIL1/FOIL2/ETCHED4; known empty differs from NULL. FTS is an internal accelerator, not independent source authority.

Schema-only packet does not populate facts, bind an executor, announce READY, change active pointers, run backfill at migration/startup or change importing behavior. ## Catalog preparation packet after physical-schema review

Generation data is immutable after successful activation. Prepare ACTIVE and explicitly requested RETIRED generations with original source/payload validation; do not silently bind a request to another active generation. Build version1 in bounded keyset batches ordered by original provider/id/language; printing phase uses provider/printing ID. At most16 original records and16MiB decoded payload per call, each record at most the existing8MiB ceiling; fetch payload one row at a time to bound memory. SQL CASE+oversize flags distinguish oversize from NULL before decoding. Stop at a soft250ms boundary between records; cancellation checked between reads/decodes/writes. Also bound each original record to1024 derived rows/8MiB normalized bytes/2048 statements and each batch to4096 derived rows/16MiB normalized bytes/4096 statements; check cancellation within face/keyword/legality loops. Exceeding a ceiling fails preparation visibly, never truncates rows or converts evidence to UNKNOWN. These are implementation ceilings, not measured physical acceptance or a relaxation of existing performance targets.

One actual database transaction per bounded batch writes facts/text/FTS and the matching progress cursor/counts. Exact progress readback reconciles ambiguous commit; unknown commit is never replayed blindly. Idempotent source-identity keys and atomic checkpoint permit process reopen/retry. Missing source or malformed unsupported payload makes preparation fail visibly; never claim partial successful results. Cancellation leaves a resumable committed prefix, never READY. No callback after acknowledged final readiness commit. Generation deletion cascades ordinary facts and explicitly deletes FTS under the existing generation owner; no deletion of retained originals merely to recover a derived index.

New imports later write derived facts inside the existing staging transactions and validate projection completeness before activation, preserving current exact artifact/consent acknowledgement semantics. Legacy preparation does not change active dataset pointers or source provenance. Do not retroactively claim old generations already have a complete index. Expose local preparation progress/error through a complete independent capability when implemented; no stub CardSearch aggregate or background network work.

Gamechanger/legalities currently lack typed canonical mapping/consistency checks. Extract their actual per-printing raw values with a versioned strict mapper: unknown/malformed/conflicting evidence is never authoritative first-row data. Deduplicate direct and source-slot membership by retained printing identity before consensus. Card-wide flags/legality require consensus over all associated retained printings: every applicable printing supplied a recognized value and all agree, otherwise UNKNOWN. Preserve known not-legal distinctly from missing. This can initially use indexed correlated aggregates; materialized consensus is a later measured optimization, not a change in truth semantics.

The numeric implementation has moved unchanged to core:common.DecimalComparisonKeys with the existing search API as a facade; the ownership follow-up passed123tests and exact-source review before catalog-owned materialization. Preserve the allowed search→catalog direction; never add catalog→search. The separate reviewed ownership packet follows the schema-only checkpoint; schema9 definitions remain unchanged.

FTS is only a proven-complete candidate accelerator: token/prefix matching cannot replace arbitrary literal containment. Compiler cases must prove candidate completeness and separately verify exact normalized literal predicates, or use a safe indexed/scalar alternative. Mixed face/printing truth fixtures must explicitly define canonical-name matching in SAME_FACE and `name:x OR set:y` with no printing; empty existential domains must preserve a true card-only branch. These remain compiler-review prerequisites, not claims that this schema enables those queries.

## Execution semantics before compiler packet

All expression operators use TRUE/FALSE/UNKNOWN; only TRUE enters results. Numeric strings outside admitted plain grammar stay UNKNOWN, and NOT cannot make missing evidence known. Source numeric comparison keys are used only against independently admitted query keys, never source equality, sorting or uniqueness. Oversize/budget failures remain typed failures/unavailable and do not become missing field values.

ANY_FACE: each face-specific leaf existentially evaluates actual faces when present, otherwise the explicit canonical field; leaf TRUE if any known match, FALSE if all applicable values are known nonmatches, UNKNOWN otherwise. Boolean composition follows that leaf reduction, so separate predicates may match different faces and NOT applies after reduction. SAME_FACE: evaluate the full expression for each actual face (or canonical field view if no actual faces), then existentially reduce with the same three-valued rule; NOT stays inside that explicit selector. CANONICAL uses only original top-level fields, never a guessed front face. Mana value/identity/layout/reserved/keywords/legality/gamechanger remain card-wide in every mode. Card name may also match the actual complete canonical name; no phrase bridges separate source field values.

Printing filters apply to one retained printing for the full expression, then existentially reduce matched printings to unique Oracle records; set+rarity+finish cannot accidentally combine unrelated printings. Thus a negated printing clause means a matching printing lacks that value with known evidence, not that no printing has it. UI must describe this as 'a printing that matches'; a future all-printings/no-printing operator would need its own syntax. Card-only expressions do not require an invented printing. Reversible membership uses actual retained source mapping. UNKNOWN print attributes do not become an ordinary false through EXISTS before negation. Independent review must confirm these explicit policies before SQL implementation.

SearchContext currently lacks actual selected collection/deck/quote policies. Preflight the whole AST and reject owned/in-deck/price execution until complete real sources exist, including inside OR/NOT. Likewise reject unsupported multi-snapshot/language/face combinations explicitly rather than silently selecting one. Direct AST depth/node/parameter/string/decimal budgets are independently validated, even when the parser was bypassed.

Cursors bind provider, exact generation/language, projection+compiler versions, normalized typed AST fingerprint, face/printing policy and deterministic name/provider/Oracle tie-break. Validate cursor before empty-result shortcuts. Readiness/source/page selection occurs in one read transaction; active changes do not substitute another generation. Explicit retained snapshot stays pinned; removed/incompatible snapshots report stale/unavailable. Pagination returns bounded complete pages only; no successful truncation when a preparation/work budget is exceeded.
